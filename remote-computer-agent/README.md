# DSH remote-computer-agent 0.1.2

Version 0.1.2 ships the short-lived QR invitation and six-digit secure pairing flow with Model Router 0.67.0. Use this matching package for the updated Host pairing and desktop transport.

Harness Desktop's native viewer uses `dsh-app://app`. Version 0.1.1 accepts this exact Origin only for a live desktop session minted by an authenticated Host; it does not enable it for HTTP API requests or other sessions. Model Router 0.63.3 carries the native viewer Origin through Desktop's HTTP bridge. Upgrade both sides when using the native application; ordinary HTTP/HTTPS viewers retain their existing exact-Origin checks.

Credentials are checked again after reading the request body and before each management action. Cached client rows from an older revision cannot issue or revoke newer tickets, and `tools/list` rechecks a live grant. Rotation during a slow request therefore cannot use the old request to revoke a fresh ticket. Temporary cooling also handles wall-clock rollback without extending its backoff beyond the configured cap.

Authentication now has separate bounded anonymous-source/global-failure and verified-client request limits, with temporary cooling and `Retry-After`. Valid clients behind a shared proxy remain usable during anonymous guessing attacks. Rotation invalidates old pairing tokens and tickets immediately. Native TLS and optional client-certificate checks have local HTTPS tests; deployment still requires user-provided certificates and a private proxy backend. See [network settings and recovery](../deploy/remote-agent/README.md) and `node --test tests/remote-auth.native.mjs` (OpenSSL required).

TypeScript machine-side runtime with a single snake_case tool catalog, versioned MCP transport and a durable SQLite operation ledger. Build with `npm ci && npm run build` in this directory; run `node dist/cli.mjs init CONFIG_JSON AUTHORIZED_ROOT`. Installation and network modes: [deployment guide](../deploy/remote-agent/README.md).

For a user-configured Windows computer, unpack the complete Windows package and double-click `start.cmd` (or run `setup.ps1`). The setup wizard defaults to short secure invitations: it selects the shared workspace, one reachable local address, trusted Host/team-Bot permission, and optional command/browser permission, then creates `private/pairing.html` with a QR code, six-digit confirmation and device fingerprint. Scan/copy the invitation into the Host's secure pairing panel within two minutes. `pair-device.cmd` refreshes an unredeemed invitation without changing tasks or permissions. Compatibility mode (`pairingMode:legacy` in an answers file) still creates `private/pairing.private.json`. No device credential is created until a secure invitation is redeemed; invitation proofs and native secrets are not printed.

The package needs `dist`, production dependencies, bundled Node or an explicit `-NodePath`, and `helpers/dsh-desktop-helper.exe` (plus `dsh-process-job.exe` when commands are enabled). The wizard registers two tasks for the current signed-in user with `InteractiveToken`/`LeastPrivilege`, starts the Agent hidden, and uses explicit full-desktop mode for the tray helper. No Windows password is stored, no VM is provisioned, and the user must remain signed in. Existing installations are backed up and preserved; configuring another installation uses another empty directory and distinct task names. A second helper still obeys the machine's exclusive desktop arbiter. The QR page is generated offline using [node-qrcode](https://github.com/soldair/node-qrcode); its camera/image counterpart is in the Host client and never uploads images for decoding.

`hostManagedBots:true` is an explicit local-admin pairing ceiling for a trusted authenticated Host to add newly created team Bots without repairing the machine for each ID. Only `Store(...,{admin:true}).pair`/the local `pair` CLI can enable it. An ordinary grant request cannot enable it; root/tool ceilings, Bot-ID validation, client revision and revocation continue to apply. Existing fixed `botIds` ceilings retain their behavior. The nonsecret flag is included in pairing metadata; the token remains in the protected pairing file.

The trusted Host resolves a pairing `secretRef`, requests a five-minute-or-shorter `/control/v1/grants` ticket, then uses the ticket at `/mcp`. These endpoints accept separate credential classes. Local pairing ceilings restrict Bot IDs, roots and tools. Tickets bind machine/client/Bot/task/attempt, revision and expiry. Caller-supplied business arguments cannot add tools or roots. Control-plane secrets and grant tokens are never tool arguments.

`Agent(config, DatabaseConstructor?)` is the direct integration entry. The injectable constructor is `better-sqlite3@13.0.3`, already used by the Host probes. `Store.pair / issue / rotate / revoke` manage local authority; `Agent.call(tool,args,grantContext,operationId)` executes the same tool catalog as HTTP. The machine identity is stored once and survives restart. MCP `params._meta["dsh/operationId"]` is assigned by the Host; never ask a model to invent it.

Writes and process starts require an operation ID. Admission is committed before side effects, duplicate IDs return original results, and a changed request using an old ID fails with `OPERATION_CONFLICT`. Restart turns unfinished records into `OUTCOME_UNKNOWN`; only status reconciliation can resolve them. This prevents duplicate admission and does not claim arbitrary scripts are transactionally exactly-once. Status and artifacts remain scoped to the original client/Bot/task/attempt. Authentication, Host/Origin and bounded throttling precede body handling.

Filesystem calls are root-relative, reject traversal/ADS/symlink escapes, check descriptors/parents and compare `expectedHash` before atomic replacement. `null` means create-only. Reads and writes are bounded; artifacts have a 256 MiB total quota. The application API does not defeat hostile same-account native processes racing filesystem names; use the dedicated OS account/container profile for the OS boundary. Existing files larger than 1 MiB cannot be replaced through `fs_write`.

`shell_exec` receives `workspaceRef:{kind:"remote",machineId,rootId,relativePath}` and either a fixed configured executable ID in `argv[0]`, or an explicitly enabled script interpreter. argv bypasses shell parsing. Default timeout is 60 seconds, maximum 30 minutes. Output capture is limited to 8 MiB and stored as scoped artifacts. Linux cancels the owned process group. Windows requires the bundled Job Object launcher, which creates its child suspended, assigns the job and closes the job on cancellation/launcher death. Missing native isolation fails explicitly. Arbitrary shell grants still carry the account's OS permissions.

Worktrees record a clean source HEAD, create a detached remote worktree and return scoped diff artifacts. Conditional integration refuses changed/dirty sources and leaves `integration-pending` on conflicts. No automatic commit occurs. Browser operations use task-specific Playwright contexts, exact allowed origins including redirects/subresources, disabled downloads/popups/service workers, snapshot references and owner checks. Browser contexts are state isolation, not an OS sandbox; profile persistence/upload/script/download APIs are not yet implemented.

Desktop calls use a local ACL-protected pipe. Default window mode requires an explicit process/interactive target. Opt-in `--desktop-mode full` enables physical monitor capture for Bots and grant-bound long-lived JPEG WebSocket watching with acknowledged mouse/keyboard takeover. Watch does not block Bot automation; acknowledged human control fences it until release. Renewing the signed grant updates the existing session without reconnecting. See [native helper](../native/windows-desktop/README.md) and [session protocol/acceptance limits](../docs/implementation/20261105-desktop-engine.md). `machine_ping` separates agent health from unverified/unavailable desktop state. Remote CLI adapter execution remains a separate Host integration gate; this runtime does not accept arbitrary CLI executable paths from models.

Reproduce native checks from the repository root with `node scripts/integration-remote-agent.mjs [--driver PATH_TO_BETTER_SQLITE3_ENTRY]`. Tests compile the C# helpers on Windows and exercise real subprocesses, cancellation, filesystem/link escapes, CAS/idempotency, unknown recovery, MCP HTTP, grants and Git integration. See the probe's explicit limitations before interpreting results as product acceptance.

### Recover an interrupted secure pairing

The importable invitation JSON omits the six-digit confirmation code. Read the code from the private pairing page on the target computer and type it in the Host. Keep that page on the target computer.

If the Agent already committed a client but the Host lost its credential, inspect the local device list first. Run `pair-device.cmd -ResetPairing` on that target computer to explicitly revoke the previous client and create a fresh invitation under the same client ID. This disconnects its old connections and grants. Refreshing an invitation without this switch never revokes an active pairing. Existing configuration, sharing scope and scheduled tasks are preserved.
