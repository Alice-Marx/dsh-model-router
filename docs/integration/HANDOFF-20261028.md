## 3. 架构地图

### 3.1 一个 Host 内的合成关系

```
.dsh-plugin/index.mjs                     ← 唯一插件入口（apply()）
  ├─ 同步段：installRouterStateStore(deferredRouterState.state)   ← 先装"等待态"资金权威
  ├─ 同步段：startBotProduct(ctx, {...})  ← 组合（见下）
  └─ 之后：MR 全部旧工具/命令/RPC 接收器在调用时解析同一 botIntegrationPolicy

packages/orchestration/src/product-composition.mjs   ← 默认产品的核心接线（633 行）
  startBotProduct(ctx, options):
    同步段：createAuthority → createPrincipalDirectory → createBotPolicy
            ctx.provide('botIntegrationPolicy', policy)     ← 在第一个 await 前提供
    有界初始路线快照（5s 超时）后：
      openProductFunding(...)        ← SQLite 资金权威 + funded 适配器（funding）
      openRemoteMachines(...)        ← 远程机器目录（machines）
      openFundingAccounts(...)       ← 资金账户目录（fundingAccounts）
      openBotSettings(...)           ← Bot 绑定设置（botSettings）
      createModelAccounting(...)     ← 模型调用准入与收据（modelAccounting）
      openTaskJournal + createTaskService + registerTaskTools   ← Task  runner（taskService）
      createBotProduct(...)          ← 冻结 DS 运行时（product），授予经 botSettings 编译
      guardMachineSecrets(...)       ← 机器控制面凭据不得进 Bot shell
      注册 remote_computer_ping/list/read 三个工具
    boot 失败：按序清理（product→machineSecrets→taskTools→machines→botSettings→
               fundingAccounts→modelAccounting→taskService→funding）后 reject，不泄漏半初始化状态
```

## 5. 资金与准入链路（改代码前必读）

这是全工程最安全关键的路径。**任何改动都可能造成多记账、漏记账或绕过预算**，改动前必须理解下面几条不变量。

### 5.1 一次 Bot 模型调用的准入链

```
DS AgentLoop → ctx.llm.stream
  → ctx.on('llm/stream') 钩子（modules/bot-runtime/index.mjs）
      → policy.modelIdentity(options)         ← 身份：优先 ALS 执行帧，其次 sessionId
      → accountStream(options, next, meta)    ← product-composition 的包装层
          → funding?.funded?.bindModelRequest?.(...)   ← MR 执行帧内的直接调用标记为托管
          → modelAccounting.stream(...)       ← 准入 + 收据
              → pricingFor = bindingFunding   ← 从绑定解析价格/上界/预算
                  → assessFundingAdmission()  ← 纯 CAS 回调内的范围检查
                      → 任一范围 unknown>0 或 reserved unknown>0 → 拒绝（fail-closed）
              → 通过：写 admitted → running → settled 收据（source: bot/aux/mr-api/cli/review）
```

来源词表适配在组合层显式完成：Bot runtime 报 `bot-session`/`bot-auxiliary`，收据 schema 封闭词表是 `bot`/`aux`——**未映射来源一律 fail-closed**，不允许发明新来源。

### 5.2 硬不变量（改动时逐条核对）

1. **只有一个资金写入者**：`sqlite-router-state.mjs` 的 `update()`。投影（`funding-projection.mjs`）在同一个 SQLite 事务内由 runs 派生，**不是第二个记账者**。
2. **CAS 回调必须纯**：`update(change)` 的 `change(candidate)` 只能改候选状态对象；不能在其中发起请求、spawn 进程或 await 外部 IO。冲突时按 revision 重算（`retrySafe`），副作用会重复执行。
3. **`unknown` 是一等状态，不是 0**：缺账单/缺用量/价格未核验时金额保持 `null` 并计入 `unknownToday/unknownMonth`；**任何范围的 unknown>0 都会拒绝后续准入**（这就是"未确认收据令其 Bot fail-closed"的机制）。不要用 0 冒充未知。
4. **0 是真实禁止付费的限额**：包括极小正金额；不使用会放过零限额的绝对 epsilon。
5. **订阅次数来自持久来源收据**：已裁剪运行、旧未插桩订阅、未归属归档都不能重置额度；来源覆盖同一 run/package 时不重复计次。
6. **收据状态机单向**：`admitted → running → reported → settled/unknown`；`settled`/`unknown` 是终态（`MODEL_RECEIPT_ALREADY_FINAL`），不可回退。唯一的新增出口是 **owner 核对**（`resolveUnknownPackage`，§4.4）。
7. **归档不可归属时保守占用**：`unassigned` 单列并计入每个受限范围，不能迁移成零费用。
8. **时区**：资金日/月沿用 Host 本地日历；epoch 记录时区，时区变更拒绝继续而非悄悄换日。

### 5.3 冻结请求与租约（model-accounting.mjs）

SDK AgentLoop 会传**冻结请求**（`signal` 不可写、对象不可扩展）。当前实现：可变请求照旧携带合并租约信号；**冻结请求由租约信号门控迭代**（quiet provider 仍会被撤权/到期中断，清理时归还迭代器）；输出边界钳制**仅在请求显式超界时**要求（未指定 `maxTokens` 不视为需钳制）。

### 5.4 已知缺口：Task/outbox 与资金不是单事务

journal 与 funding store 是**两个独立 SQLite 连接**。任务被 journal claim（状态 → running）之后，backend 的 `run` 才做资金准入与预占。这中间的崩溃窗口内：任务在 journal 里是 running 但无预占——重启后 `journal.recover` 标记 `needs-reconciliation`（**fail-closed，正确但不原子**：不花钱、不派活，但需要人工核对）。

要做成原子化，需要二选一（都会动到已验证路径，回归成本高）：
- **共享连接**：让 journal 与 router state 共用一个 `Database` 句柄，把 claim 与预占放进同一事务；需重写两者的连接生命周期、迁移与 close 语义。
- **两阶段提交**：journal 侧引入 prepare/commit 状态与补偿日志，backout 路径要能撤销已发布的预占。

两者都要留审计痕迹，并需重跑 29 项 journal 原生 + 崩溃恢复探针 + 默认探针 + 资金探针 33 项。

## 6. 默认真实 rc.3 宿主探针的产品流程（改探针前必读）

`scripts/integration-product-default.mjs` 是默认产品的端到端探针（现 35 项，原 28 项加 7 项计划/冷重放检查）。它的流程顺序是**产品契约**，不能为了省事调整：

6. 机器配对/授权/受控读/撤销/重授。
7. 停用资金范围 → 零分发。
8. **重启宿主** → 冷启动重建断言。

## 9. 踩坑与约束（逐条都是真实代价换来的）

### 9.1 台账与文件的机械规则

1. **施工包 completed 的硬门槛**：`scripts/integration-progress.mjs` 要求 completed 施工包的**全部验收场景 status=passed**、全部子步骤 completed、依赖全部 completed，且**非 M0 施工包还要求 M0 四个门禁全部 completed**。所以"交付物已验证"的包也必须保持 `in_progress`——施工包完成度不能代替产品验收。
2. **换行**：`tasks.json` 与 `behavior-audit.json` 是 **CRLF + 两空格缩进**；`package.json` 是 **LF**。改 JSON 用脚本做往返守卫（读原文本判断换行再写回），不要整体重排造成大片噪音。
3. **证据路径校验**：`validateEvidence` 要求每条证据是**可移植的相对路径且指向真实文件**（禁 `..`、绝对路径、反斜杠、`tmp`/`node_modules`/`.git` 开头）。写错路径会让 `integration:check` 直接失败。
4. **`package.json` files 必须逐文件**：目录项会被闭包测试拒绝；新模块 import 进 `.dsh-plugin/index.mjs` 闭包后，必须把**每一个**被导入文件加进 files（当前 252 项）。
5. **临时脚本必须是 `.mjs`**（项目 ESM），且内联 `node -e` 在 Windows 下反斜杠/引号会被吞——含双引号或路径的 JS 一律写脚本文件。
6. **`assert.rejects` 对同步抛出的函数不成立**：要包一层 `async () => ...`。
7. 根目录已有早前会话留下的 `scripts/tmp-ds-closure.mjs` 与 `scripts/tmp-update-package.mjs`，**未擅动**；自己用完的临时脚本要删掉。

### 9.2 代码层面的坑

1. **`discoverConfiguredRoutes` 不能在执行上下文外调用**：它内部走 `policy.filterRoutes`，无上下文会抛 `CALL_CONTEXT_REQUIRED`。组合的路线目录改为直接遍历 `ctx.llm` 原始目录。
2. **SDK AgentLoop 传冻结请求**：`signal` 不可写、对象不可扩展。准入与租约必须兼容（见 §5.3）。
3. **来源词表封闭**：receipt schema 只认 `bot/aux/mr-api/cli/review`；Bot runtime 报的是 `bot-session/bot-auxiliary`，适配在组合层显式做，未映射一律 fail-closed。
4. **`grantFor` 必须容忍机器目录未开/已关**：boot 失败清理后目录已关闭，直接 `machines?.scopes()` 会抛 `MACHINE_DIRECTORY_CLOSED` 挂起 DS lifecycle；要 try/catch 降级为无机器权限。
5. **探针首次 `api('state')` 不能 race**：资金/机器权威先于 DS 通道就绪时会 404；必须 `ready()` 等待产品通道。
6. **jsdom UI 测试无法模拟文本输入**：`tests/bot-runtime-ui.test.mjs` 在 DOM 安装前就 import React，React 的 input 事件支持探测因此为否，`input`/`change` 不触发 onChange（click 不受影响）。所以页面测试只覆盖渲染与门控；输入交互语义靠真实宿主探针与原生套件覆盖。
7. **计划校验的可执行路径正则**：必须同时覆盖 `C:\\`、`C:/`、`/usr/...`、`./`、`../`、`..\\` 与**含空格**路径；判定用"分隔符 + 可执行扩展名"，裸文件名不算路径。
8. **未确认收据会阻塞其 Bot 与所在账户范围**：`assessFundingAdmission` 见 unknown 即拒；所以"Bot 自己驱动核对"不可行，恢复路径必须是 owner 动作。
9. **中断执行留下的预占同时贡献估算金额与 unknown 计数**：只解决 run 包里不够，必须同事务释放预占。
10. **journal 测试的 `now` 值必须小于 store(t) 辅助的 1000ms runner 租约**（早前踩过）。
