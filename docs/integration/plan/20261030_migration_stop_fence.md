# 多 Host 停写与迁移激活的持续栅栏设计

状态：**设计，尚未实现或验收**。适用 W03.4/W06.3 的原位迁移和激活后回退；本设计不授权访问真实用户数据，不把预览、配置阶段或单库备份当成完整迁移。文中路径均为仓库内代码定位，不是用户路径。未知条件一律拒绝继续。

## 1. 安全目标与范围

在一个明确列出的数据域及物理存储身份上，建立覆盖整个关键区间的排他事实：从首个一致捕获前、配置/程序切换和恢复，到新世代唯一写入权确定，旧写者都不能写入；若进行激活后回退，必须先排空并导出**最新**新世代数据，然后再交接写入权。必须阻止新的旧入口与自动重启，并排空已启动的工作；单次检查、仅持有文件名或进程列表不构成持续证明。

最初只支持经可验证的本机受控启动器与受控存储的模式。多个进程共享同一物理数据时也算多 Host；跨机器/网络共享须有各机器可信控制器和存储端持续写入栅栏，或离线且可验证的存储快照。不能证明全部写者和所有重启入口受到约束时，保持仅预览、`activationSupported=false`。跨机器发现失败、网络分区、存储锁语义未知不允许乐观继续。

### 1.1 写者清单，按数据域而不是按程序名

| 写者或入口 | 涉及的数据 | 需证明的行为 |
|---|---|---|
| 各个已运行的 DSH Desktop/Web Host，包含同时加载的旧 DS Bot、旧 MR、统一产品；各 profile、不同启动目录、快捷方式、服务和定时重启 | Bot `state.json`、记忆、group/team/session 索引、MR JSON/SQLite、Task/收据、配置与 profile | 实际 Host 世代、启动上下文和所有共享域；停止新工作、完成在途写入及关闭句柄 |
| SDK Host、Session/附件服务、SDK profile/包协调器 | Session/历史分段/附件、工作区注册、profile 清单及 patch | 所有受控进程和排队写入已停；profile 解析本身可能写源，预览不调用写入型 loader |
| Bot 调度、记忆 review、扫描/usage、side chat、搜索、连接器及 MCP 子进程 | 不同队列、日志、`usage.sqlite`、密钥/外部状态 | 停止新派发，等待在途操作；外部服务状态不因本地停机自动完成 |
| MR/Task/资金 writer、CLI 和其后代、远程 Agent / 桌面 helper | Task/attempt/outbox、holds、计费/收据、工作区/外部副作用、Agent 原操作与产物 | 排空或确认取消；unknown、未观察停止、未结 hold 保留，不能用“进程不存在”推断没发生外部效果 |
| 用户或第三方编辑器、同步/备份程序、数据库工具、另一个旧版 Host 或具有不同路径别名的进程 | 任意被迁移域，包括通过硬链接、junction、挂载或网络共享访问 | 被纳入可信控制与权限栅栏；不认识/不能约束时视为未知写者并拒绝激活 |
| 外部凭据库、云连接器及浏览器 profile | 系统和服务端状态、Cookie/权限、正在运行的浏览器句柄 | 可迁移性和重连单列；凭本地文件哈希不能声称外部状态已停或完整 |

资源清单由可信 owner 本地协调器按显式 source/target 和有效启动层生成，覆盖物理路径身份、别名、祖先/子树关系和同一数据库的多个入口；路径字符串相等不是身份相等。配置引用的未知 include、动态 home、未提供 launcher 参数、无法解析的环境、不可识别应用或不支持的远程共享，均返回需补充或不支持；不猜它们不存在。完整清单须包含 DS、SDK、MR、产品与非本程序可能写者，不能把某些已知 pid 的枚举当成全域穷尽证明。私有清单、凭据和真实路径不进入公开证据或模型上下文。

## 2. 现有能力和明确缺口

1. `packages/orchestration/src/migration-startup-gate.mjs` 检查单个 gate，并在 `.dsh-plugin/index.mjs` 的新产品 writer 初始化之前执行。它只约束调用这个 gate 的新启动；**不能暂停已经运行的 Host，也不能约束不认识 gate 的旧版或第三方写者**。启动时一次读 gate 也不构成与迁移协调器原子互斥：在读取后、实际打开 writer 前仍可能开始迁移。
2. `packages/orchestration/src/migration-configuration-commit.mjs` 有私有原字节计划、哈希链接的阶段日志、文件身份复查和激活前恢复。其进程协调文件 `migration-gate.lock` 是本地 PID/文件实现；保护单次调用而非整个跨 Host 写者集合。`activationSupported=false` 和 `postActivationRollbackSupported=false` 必须保持，直到本设计的独立门槛完成。计划中的 `stopped-hosts` 等字符串不是已验证回执。
3. 冻结 DS 的 `modules/bot-runtime/vendor/ds-bot/src/host/home-lock.js` 使用文件、PID、主机名、token 和心跳；它并非内核级持久写栅栏。更关键的是 `src/host/store.js` 在锁不可用时 `lockBroken` 后仍可继续写：禁止把制造锁故障、占有锁文件或等待心跳超时当成对旧 DS 的强制停写。冻结源码不修改。
4. `.dsh-plugin/shared/router-state.mjs` 的旧 JSON 写锁以及 `packages/orchestration/src/sqlite-router-state.mjs` 的 SQLite 事务/权威切换仅约束各自实现的参与者；不自动封住旧 DS、SDK、其他 DB、已打开的外部文件描述符或网络共享上的未知实现。即使独占某个 DB，也不代表其余域形成了同一时间点。
5. `migration-snapshot.mjs` 的重复清点只能发现部分漂移；`migration-data-archive.mjs` 明确 `databaseConsistent=false` / `crossDomainConsistent=false`；`migration-ledger-export.mjs` 的 SQLite 备份仅对一个数据库一致。它们都是必要材料，均不是全局停写回执。
6. 当前固定 DSH rc.3 `dsh-app-boot` 的 `loadProfile()` 会初始化/规范化 profile、移除投影，`loadProfileDirectory()` 可删除 retired bundle 后回写 manifest。清点/预览不能对源 profile 直接调用这些有写副作用的入口，应继续使用已实现的稳定读与纯组合方式。

## 3. 新增可信能力：准入、排空与持续排他

### 3.1 持久准入权威与范围

新增 owner-only 的受信任协调器与启动器协议，定义版本化的 storage set、物理根/数据库身份、程序和配置指纹、每一已知启动入口、Host 版本/世代及单调 fencing generation。正式实现前先确定锁实现、权限边界、故障恢复和跨平台语义；不把用户可填 JSON、MCP 票据、模型输出或自报 `stopped=true` 当成权威。

受支持的新 Host/launcher 在**访问任何迁移数据或创建 writer 之前**与同一准入权威握手：取得当前 generation 的持有型共享准入，随后再核对 durable maintenance intent、存储身份和配置世代；持有准入直到所有 writer/队列/数据库/子进程完成关闭。每个会独立重启或绕开父进程的写者也需单独登记或被操作系统控制器包含。任何异步写入路径在 writer 已撤销后不得继续提交。读取 gate → 创建 writer 的间隙必须通过共享/排他准入、再检查形成有验证的原子协议，而不是增加一次路径读取。

协调器持久写入 maintenance intent 后请求排他准入，拒绝新的共享准入，并等待既有共享准入退出；不能取得就停止。它必须真实保持排他资源直到快照、验证、最终切换及新世代准入状态均安全完成。共享准入丢失、存储身份变化、权限变化、owner 世代更换或排他权威不可验证时，所有后续修改立即停止，且尚未确认的在途效果留作 unknown。

本机可以研究独立 SQLite 控制连接持有 `BEGIN IMMEDIATE` 或经测试的原生内核锁，作为**合作进程**的协调部件；必须证明所有被保护入口统一参加、锁文件/数据库真实身份固定、进程退出后规则正确、启动 gate 和锁的次序无竞态，且遵守对应文件系统语义。仅将一个 SQLite 行/时间戳/布尔值写盘不是持有型锁，也不保证对旧程序生效。不可自动假设 SMB/NFS 上 SQLite 或本地锁能提供跨机器故障语义。

### 3.2 不认识 gate 的旧程序和第三方写者

旧程序不会凭新 gate 自行停止。必须同时满足下列全部条件，才能把一个旧入口从“未知”转为受控：

- 确定所有能够访问该存储的用户、机器、launcher、守护进程、计划任务和可自动重启入口的闭包；未知内容不能填“无”。
- 在可信的操作系统/服务管理与存储权限边界中，阻止这些入口重新创建写者，且此限制覆盖 coordinator 和机器重启期间；本地 ACL、单独账户、受控服务或隔离介质能否满足，必须逐平台验证。仅同用户自愿约定不构成强制隔离。
- 通过可持有的真实进程/服务身份确认已知旧 Host、外部 writer 和被纳入范围的子进程全部结束或可验证排空，且打开的写句柄无法存活；如果权限不能枚举或关闭句柄，保持 unknown。禁止以 PID 相同/不同或心跳超时推断进程已安全结束，禁止自动杀死无法归属的进程或删除活锁。
- 在受控栅栏仍保持时，对磁盘权限、挂载目标、路径别名和所声明的 Host 范围再验证。权限变更并不会撤销旧进程已经打开的句柄；仅修改 ACL 或只读属性不能替代排空。

当无法穷尽共享机器和外部写者，或者无法排除同账户进程绕过启动器、外部同步软件改写、外部服务异步变化，应拒绝原位激活。可允许用户选择显式离线源和经验证的物理隔离快照，但来源与目标、快照时点、已知未覆盖范围和后续新数据回退必须另有完整证据；更不能将静态两次 hash 相同视为停写证明。

### 3.3 跨机器与故障假设

分布式支持需要每台参与机器上的受信任 controller 和**存储端**认可的 fencing token/单写者代际；过期 token 必须在实际写入处被拒绝，不能依赖 controller 心跳或客户端时钟自觉停写。平台文件系统没有 token 强制能力时，本设计不提供跨机器写安全保证。必须对未知节点、锁丢失、重连旧世代、重复世代和时钟跳变拒绝；网络断开或 controller 无法认证时是 unknown，不是自动放行。

旧文件访问无法识别 token 时，只能借可靠存储/账户权限和入口控制强制隔离，或转为真正离线源；持久运维隔离必须覆盖机器重启及无人恢复。若平台或用户环境无法实现并验证该控制，原位迁移明确不支持，允许继续只读预览并说明所缺证据。

## 4. 状态机与崩溃恢复

所有阶段在私有 append-only journal 记录意图和结果，并绑定 operation ID、代际、域集、物理身份、完整来源/目标映射和各域快照及对账指纹；对外只输出固定诊断码、界限和计数。日志自身完整性和受信存储权限也要验证；普通哈希链不能单独认证一个可被同账户攻击者整体替换的记录。

1. **inspect**：只读收集显式 profile/launcher、数据域、旧/新程序和可能的写者；未知即 blocked。只读源不创建锁文件、修改 SDK profile、停用户进程或读取秘密进模型。
2. **intent + quarantine**：协调器登记本次迁移、持久禁新准入；通过受控 launcher / OS / 存储阻止旧入口重启。隔离控制必须先于确认停写，且可在协调器进程死亡后持续或安全地保证不会放行。
3. **drain + exclusive**：请求活跃新 Host 停派发，显式等待 Task/模型/CLI/Agent/Session/后台写入关闭，确认原始停止/收据状态；取得并持续持有排他准入及所有其他必要域控制。unknown、已失联 host、holds 或不可确认的外部作用均阻塞切换。确认只对所覆盖的数据域成立。
4. **capture**：持有整个停写栅栏，逐库采用原生一致备份，再保存非数据库文件/配置和必要的 OS 元数据；做完整身份/引用/资金/收据对账，记录源/目标稳定映射和程序指纹；任何域漏选、变化、数据不可读取或空间不足都停止。单库快照与普通目录捕获之间不能让写者恢复。
5. **maintenance / install / validate**：复用已有配置事务的计划与阶段恢复，但在每次不可逆发布前校验活的排他授权、物理身份、存储隔离、所需域快照和原始收据；任何旧版本的失控入口出现，停止并保留其实际影响。此阶段不派发产品模型或执行任务。
6. **activate**：仅在完整停止和所有数据/程序/权限/兼容性门槛成立时，持有排他权将新 generation 与唯一资金权威的意图、数据状态、允许启动器代际和提交记录按可恢复协议确定。持久 gate 的 `committed` 只是其中一项，不能代替跨域事务；无法证明顺序和持久性则保持 validating/unknown。旧入口必须持续被排除，直到已确认不可能再写同一权威数据。
7. **release / start**：完成 journal/gate/新代际持久记录并复查后，通过受控启动器交接新世代共享准入。先启动一个无真实模型的健康检查，确认身份、数据、唯一 writer 和配置；额外启动受同一准入协议约束。失败时维持隔离，不把成功启动当成全功能验收。

协调器崩溃可能释放本进程持有的内核锁。**禁止把锁自然释放直接解释为迁移成功或许可旧程序写入**：持久的 maintenance gate 与独立的旧入口隔离必须仍在；接管者在验证日志/源与目标身份后重新获得完整栅栏、核对所有持久副作用，再从已知安全阶段 resume 或执行激活前回退。若独立隔离在崩溃后也失效，必须视为可能出现旧写者，禁止恢复/激活，重新建立停写与全域一致捕获并人工核对实际改动。未知 gate、损坏日志、未确认的中间副作用、代际不一致或第三方编辑保持停机与数据保全。

进程退出 fixture 只能证明所测进程中断恢复，不能代替断电、硬件缓存、底层存储语义或 Windows ACL/文件句柄关闭证据。真实多 Host 和机器重启需单独验证。

## 5. 激活后回退与二次升级

回退重新执行同一套准入阻断、排空、外部写者隔离和持续持有流程；不能复用激活前的过期证明。保存**新世代最新** Bot/Session/记忆/附件/usage，Task/plan/package/attempt/operation/outbox/依赖/去重墓碑/收据、原始资金/账户/holds 及机器/连接器引用；独立 SQLite 均使用各自一致备份并在全域停写期间完成。未知收据、无法确认停止的外部操作、活动任务或未结 holds 均不允许变成成功或释放资源。

`sqlite-router-state.mjs` 的现有资金 `rollback()` 将最新金额导回旧表示，并拒绝 holds 和非 `succeeded/failed/cancelled` 的任务。不要单独放宽该 guard。尤其 `blocked` 在 `task-journal.mjs` 的 `terminalRetry` 内，具有可重试性；若未来要允许某个未开始 blocked/skipped 项，必须验证原 attempt 未开始的可信记录、完整任务/依赖/去重导出、写者持续栅栏，以及重新升级后原身份与幂等性；缺任一证明拒绝。旧程序不能理解的新域保存在受控只读档案，下一次升级需无冲突重放或继续保留，不能用激活前备份覆盖已新增费用和任务。

先完成最新数据导出与双向对账，再切程序/配置/唯一资金权威；旧程序读新库的能力、外部系统副作用与存储位置移动需各自验收。崩溃发生在 rollback intent、资金标记、旧目标写入或 generation 切换之间时，仍不得自动启动另一写者，须按实际 journal 和权威身份恢复。

## 6. 失败语义和可交付切片

以下均是阻塞，不允许自动“修复”成通过：未知 launcher/Host；活动或权限不可见的进程；重启或写入无法持续拦截；旧版本不认识 gate 且 OS 隔离不可靠；挂载/路径/硬链接身份不稳定；远端 controller 失联；不可验证的锁语义；SQLite busy 或身份漂移；在途外部操作及收据 unknown；不完整域/OS 元数据；配置、程序或备份不可信；源被修改；退回后无法保留新数据。诊断应区分 `blocked`、`unknown` 与已确认未开始，不能把超时、撤权或取消当作回滚。

建议可并行、互不冒充验收的实现顺序：

1. 只读 writer/launcher/domain 清点和物理身份诊断，以显式输入驱动；未知标为 unknown。它不能取得停写证明。
2. 受控单机 launcher/Host 的共享准入与迁移独占栅栏原型，仅 synthetic test homes；实现真实子进程竞争、gate/锁 race 与崩溃接管。旧 Host 的外部隔离是独立平台门槛。
3. 只读最新回退准备诊断，检查原任务状态、hold、原收据及与完整备份的绑定；不改变现有资金 rollback guard。
4. OS/launcher 隔离适配器在专用账户和设备上验证真实旧进程停写、写句柄、自动重启和 coordinator 死亡；覆盖相应 DS/SDK/MR 数据域。隔离不起作用则保持仅预览。
5. 受控跨域捕获/验证与可恢复提交编排，之后才考虑激活；跨机器支持另行设计实际存储 fencing token，无有效平台原语不开放。

新增代码必须是冻结 DS/SDK 外层适配；模型不可指定任意迁移路径/SQL/操作系统命令。新程序正式接线、台账标记和发布包纳入由主代理统一审查。

## 7. 必测负例和完成门槛

- 两个 Host 同时准入、一个在 gate 检查后暂停并与协调器争用；证明 migration 排他得到时任何新 writer 都未越过第二次检查，已打开的写者被等待。
- 旧 DS 锁不可用时仍写的真实负例；旧 MR、SDK profile loader、旧 launcher 不读新 gate 的负例。构造真实子进程和合成数据，不使用用户 profile。
