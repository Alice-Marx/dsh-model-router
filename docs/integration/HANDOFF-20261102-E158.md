## 1. Windows 默认 managed backend 与停止证明

Windows 产品默认使用 managed ConPTY。helper 在 Job 内以 `CREATE_SUSPENDED` 原子创建宿主，ConPTY 控制帧与 raw data 通道隔离，并以 PID + creation start identity 绑定后续帧。manager 先建立 session、注册 data/hostExit/treeClosed/outputClosed/outputDropped/controlLost/closed 监听，再唯一 `await proc.resume()`；启动负例确认 resume 前用户 marker 不存在。

只有同一 backend 身份的 `treeClosed` 且 `proof=windows-job-active-process-zero`、`activeProcesses=0` 才设置 `treeClosed/stopConfirmed/stopped`。hostExit、外部 PID 消失、helper close、control loss 或 stop timeout 均不制造 typed0。hostExit、treeClosed、outputClosed 分开：host 先退出而后代仍活时，session、capacity、stop、orphan/lifetime sweep 与 long-poll 继续保留；late tree/output/truncation/drop/control 事件通过同一 id 更新，`onSessionEnd` 仅真实 host exit 时一次，最终 UI 结束等待 tree + output + buffer drain。

POSIX 保留旧 PTY/pipe backend，继续明确 `treeTracking:false`、`stopConfirmed:false`；本切片没有真实 POSIX tree proof，也不伪造。

## 2. 私有目录、协议与 GPT 纠偏

factory 把 caller 传入的 canonical 现有目录只当父目录，在其中 `mkdtemp` 创建唯一 `dsh-managed-*` child；只有该 child 属于 factory。清理前重验父/child 的 realpath、相对范围、目录类型和 dev/ino identity，绝不递归删除 caller 父目录或 sentinel。私有 child 使用 owner-only protected DACL，helper 重验 owner/DACL；creator watchdog 与 Job 限制共同负责回收，独立原生 `CREATE_BREAKAWAY_FROM_JOB` 负例实际返回 Win32 5、未创建逃逸后代。

输出队列满时通过 `outputDropped` 明确累计 `bytesDropped` 并设置 truncation，不静默丢字；resize 使用单调 `requestId`，迟到响应不能串到后续请求。控制帧有严格字段、状态顺序和 identity 校验，raw 输出中的伪造 `treeClosed/hostExit/stopRequested` JSON 不改变状态。

GPT 的实际纠偏包括：补 C# `System.Diagnostics` 编译引用；用已验证的 PowerShell `Set-Acl` 设置私有目录并在 C# 重验 owner/DACL；修正 named-pipe 名称两端一致性；按 node-pty ConPTY 启动方式设置 `STARTF_USESTDHANDLES`、三个标准句柄保持 null、`bInheritHandles=false`；修正输出 drain、控制读取边界及失败清理。Kimi 的静态/单元观察与真实 Windows 执行结论分开记录。

host-exit fixture 的 `detached:true + unref` 只让 child 超越 Node parent 生命周期，不请求 `CREATE_BREAKAWAY_FROM_JOB`，不等于 Job breakaway；真正的原生 breakaway 拒绝测试独立保留。

## 5. C 矩阵 verdict 与 product proof 严格分开

最终 21/21 是测试 verdict，不等于每项都有产品 stop proof。以下用例即使实际登记 PID+identity 均已回收，product proof 仍明确为 **unknown**：

- preCreate、created-suspended、resumed、hostExited 四屏障的 creator death 与 helper death；
- QueryJob failure、QueryJob bad length；
- stop timeout；
- data channel dispose fault；
- duplicate `started` 控制帧。

外部 PID 消失不能转换成 typed0。control EOF 是正常受控停止路径：观察到 `stopRequested.reason=control-ended`、无 control lost，随后真实 typed active0。late `hostExit` 只在先前真实 stop 已产生 typed0 后注入，证明不来自迟到帧；伪控制输出只在真实 stop 后得到 typed0。原生 breakaway 拒绝是负例安全证据，不冒充一次产品 stop proof。
