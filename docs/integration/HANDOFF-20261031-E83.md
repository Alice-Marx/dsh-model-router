## 1. 本轮交付

- `launchMigrationLinuxProcessTree` 新增 `cgroupRoot`，默认 `/sys/fs/cgroup`，可指向 delegated 子目录。
- JS/Python 要求 realpath 位于 cgroupfs 内、目录归当前有效用户所有；nobody 使用 root 拥有的根会被 `MIGRATION_LINUX_QUARANTINE_CGROUP_UNTRUSTED` 拒绝。
- Python 新增 `/proc/self/cgroup` 校验：supervisor 必须已经位于 delegated 根或后代中，否则 `MIGRATION_LINUX_QUARANTINE_SUPERVISOR_OUTSIDE`。
- E82 的 exec 前 membership、cgroup.kill、空 procs receipt、显式 rmdir 和三个 false 边界字段不变。
- 测试改为显式 `randomUUID` import，避免 root 环境隐式全局差异。

## 2. 为什么必须是这个模型

1. `systemd-run --scope --uid=nobody -p Delegate=yes` 的 scope 目录仍归 root，不能直接写，未算通过。
2. 仅 chown delegated 目录仍不足以写子 `cgroup.procs`；即使补父级 procs，supervisor 在根外时共同祖先仍是系统根，仍失败。
3. 正确方式：委托方配置目录与父级 procs 权限，并先让 supervisor 进入 delegated 根，再降权运行。测试仅用临时目录和 setpriv，没有永久账户、服务或 sudo 规则。
