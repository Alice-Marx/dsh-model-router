## 1. 来源域私有 artifact 与真实正例

来源域模块从**实际已验证的 data/ledger archives** 构造、保存并重验 owner-only、operation-bound 的私有 artifact。绑定对象包括实际 operation、capture-verified journal、域 root/布局和固定 input digest。财务 export 必须来自真实捕获账本的重导出，caller inline export 不能冒充捕获来源。

最终正例使用真实 schema 5 ledger（经实际 task-journal DDL 路径生成）、matching router v4 marker 和与 Bot 引用匹配的真实 SDK v4 Session，财务 ledger 实际进入审计结果。通用非法 ledger 与缺 marker 保持 `blocked`；缺 usage、timezone 等上下文仍保留对应的 `needs-context` 诊断，不被改写为 `audited`。

财务上下文条件必须按原义理解：`input.usageExport !== null`。省略 `usageExport` 会保留 `USAGE_EXPORT_REQUIRED`，显式 `null` 会抑制该诊断；不得把显式 `null` 宣传为保留诊断。

## 2. 编排权威与原始 verdict

编排只从实际已验证的 operation 和实际 `capture-verified` row 导出 independent expected，不用 caller context 代替权威来源。以下替换或篡改均被拒绝，且不覆盖原 artifact：

- 另一 operation 的完整 artifact；
- 另一 operation 的完整、 otherwise-valid data archive，以及被替换的 ledger archive；
- 已 pin domain journal step 的篡改；
- 绑定后的 root 或固定 input 漂移。

原始 `needs-context` 与 `blocked` verdict 在 maintenance/release 重验中保持。这里证明的是组合层对实际 operation/journal/capture 的绑定；独立 domain primitive 仍不自行认证 caller context。

## 3. 有界读取、崩溃与恢复

artifact 通过有界 descriptor 读取并重验，拒绝 symlink、hardlink、文件 identity 漂移、目录漂移、 oversized 或读取期间增长的 artifact。完整 artifact 的 cold resume 可省略重复 input，只重验既有 artifact；创建新 artifact 仍必须提供固定 input。partial artifact 不覆盖，恢复原 root 拒绝，显式新 root 加固定 input 才能重建；已 pin root 不能漂移。

native 覆盖在 artifact 完成、domain journal 写入前真实 **exit 86**，随后由**新 Node 进程** cold resume。恢复后 artifact bytes 与 mtime 不变，journal 只新增唯一 `domain-audit-verified` step。另覆盖 domain step 后 exit 86 的接管重验，以及 partial artifact 保留与显式新 root 恢复；没有用模拟成功替代真实崩溃。

## 4. 覆盖与 attestation 严格边界

覆盖固定为 **`captured-declared-roots-only`**，`crossDomainConsistent=false`。它不证明机器全域、生产/远程停写、外部服务状态、激活后回滚或完整业务迁移。

新 domain 模块**不等于** complete-domains attestation 已接通。verifier 目前只支持 artifact 与 money 的 automatic observation；其余四种 automatic（`stopped-hosts`、`complete-domains`、`consistent-backups`、`permissions`）及全部 platform-evidence 仍 unsupported。manual 仅 `declaration-only`，不是已认证 actor 或自动证明。

`allowed`、`activationSupported`、`postActivationRollbackSupported`、`stopWriteProvable`、`generationAvailable` 全部 false。C1–C10 仍全 false，C9 仍为 `PRODUCT_ADMISSION_PARTICIPANTS_ONLY`。
