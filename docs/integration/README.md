# 一体化工程资料

`plan/` 保存用户确认的 1.1 方案、验收矩阵、评审记录和随附来源。方案中的“本轮未实施”等描述属于定稿时的历史状态，当前执行状态以本目录的 `PROGRESS.md`、`tasks.json` 和证据记录为准。

## 持续推进

1. 开始工作先读 `PROGRESS.md`，运行 `npm run integration:status`。
2. 以 `tasks.json` 的 W01–W20 和 G1–G4 选择未完成的工作，核对依赖。
3. 完成子任务后添加 `evidence/` 中的可移植证据，更新台账与进度说明。
4. 运行 `npm run integration:check` 和相关验证；只把实际覆盖的内容标为完成。
5. 更新 `PROGRESS.md` 的下一步、限制与复现命令，保留失败证据。

`scope.json` 固定32项需求、40组功能和63个验收场景。`feature-inventory.json` 是冻结提交的源码出处及静态注册清单，不等同于完整用户行为已验收。修改方案范围需要显式修订记录，不能为了通过检查删验收项。

## 证据与隐私

提交简洁、脱敏的结果、版本、命令、日志摘要和校验值。完整本机日志、测试数据库、下载源码及机器配置放在已忽略的 `tmp/integration/`；用户真实 DSH 数据、端点和凭据不放进本目录。

机器记录区分已连通的测试目标和生产部署。`deployment-status.json` 当前登记了已实测的Ubuntu与Win10别名；产品agent、常开宿主与休眠拓扑尚未完成。平台证据只覆盖报告中的Node/OS/架构，不能外推到Electron或其他组合。
