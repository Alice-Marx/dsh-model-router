# 模型路由工作台：从界面到实际使用

适用版本：`@ljwei-stak/model-router-galgame@0.9.0`，DeepSeek Harness Desktop `0.2.0-rc.1`。安装步骤见[安装与验证指南](../INSTALLATION_GUIDE.zh.md)。本文专门说明左侧 **模型路由** 工作台怎么用，以及何时才会真正调用模型或官方 CLI。

![模型路由工作台六步操作示意](assets/workbench-usage.svg)

> 图为不含个人任务内容的操作示意，非桌面实拍。供应商、模型与工具的数量会随你在 Harness 中的配置变化；“已登记”或“已安装”不等于账号已经登录且有调用权限。

## 先理解截图上的控件

| 界面位置 | 作用 | 操作要点 |
| --- | --- | --- |
| 顶部“6 个供应商 · 30 条路线” | 当前从 Harness **模型目录**读到的数量。 | 这是目录数量，不代表 30 条路线都已登录、可用或有价格。 |
| 左侧“任务描述” | 输入要分析的任务文本。 | 写清具体交付物、约束和验收标准；本页不会自动读取工作区文件。 |
| “单任务 / 团队分工 / 指定模型” | 选择一次路线推荐、把复合任务拆成有依赖关系的工作包，或整项任务只交给一个模型。 | “生成路由建议”只生成计划；要执行请用下方“在工作台执行”（只读），可编辑团队仍在官方会话中启动。 |
| “本次估算预算（USD）” | 给本次本地规划一个估价目标。 | `0` 表示不设目标；截图里的 `10` 是 10 美元估价目标，**不是扣费上限**。 |
| “生成路由建议” | 在本机分析文本和已登记路线。 | 点击后向下滚动，在“逐模型价格与能力”卡片后查看“路由建议”。此按钮不会向模型发送任务。 |
| 右侧“模型目录”及“搜索路线” | 查看和过滤 `provider/model` 的准确名称。 | 搜索只过滤显示；“刷新”重新读取目录，不能在这里添加账号或模型。 |
| “在工作台执行” | 沿用任务描述与规划模式，选路由方案、填工作区绝对路径（留空沿用上次运行），先**预览执行计划**再确认执行。 | 预览列出路线、工作包、预估费用、预算检查和所有需确认的原因（超预算、不经沙箱启动 CLI）；按“全部确认并执行”前不会调用模型。只读执行；可编辑任务仍在官方会话中开始。 |
| 下方“逐模型价格与能力” | 为目录中**每条要比较的路线**填写自己掌握的质量、价格和能力资料。 | 配完一条点“保存此模型”，再切换下一条。更改后要重新生成建议。 |
| 更下方“官方工具” | 检测、安装、修复 Kimi、Claude、Codex、MiniMax、MiMo、Grok、ZCode 等固定注册表工具。 | 仅当卡片显示执行入口已核验，才可尝试在官方会话中托管调用；登录和模型权限还需核对。 |

右侧列表里的“推理等级”来自目录元数据，不是价格、质量分或账号可用状态。左侧“Gal 模块”是独立功能，与当前路由任务无关。

## 第一次使用：先配置可比较的路线

1. 在 DeepSeek Harness 的官方**模型**设置中添加你打算用的供应商、模型和凭据。返回“模型路由”，点模型目录的**刷新**。列表中应出现准确的 `provider/model`。插件不收集或保存 API Key。
2. 向下滚动到**逐模型价格与能力**，从“模型路线”下拉框选择一条准确路线。不要把右侧显示名当作任意可用的 CLI 模型名。
3. 填“质量评分（0–100，自报）”。这是**你对该模型完成本类任务能力的估值**，不是官方排名。希望比较“经济型”和“高质量”路线时，两者都要填写；没有依据可以留空，并接受建议的不确定性。
4. 把你核对过的**输入单价**和**输出单价**同时填入，单位均为 **USD / 百万 token**。不掌握实时价格就两项都留空；不要把未知写成 `0`。缓存价格可选，留空时按普通输入价估算。
5. “擅长方向”可填英文小写标签，逗号分隔，例如 `writing, research` 或 `code, reasoning`。它们仍是你提供的资料。若某厂商 CLI 使用的模型名与 Harness 目录 ID 不同，且你已在该 CLI 中验证，可填“官方 CLI 模型名”；否则留空。ZCode 3.14.3 不支持单次任务切换模型，不要为它填此项。
6. 点**保存此模型**。切换路线，重复配置其他打算参与比较的模型。看到“未配置，价格与质量来源未知”时，该路线没有你提供的资料；看到“已配置能力，价格未知”时，仍无法可靠估价。

> **不要粘贴真实 API Key、登录令牌或密码。** 模型档案只收质量、价格、专长和可选 CLI 模型名。费用来自你填写的单价和预估 token 数，实际消费请看厂商账单。路由如何计算可看 [README 的算法说明](../README.zh.md#路由算法从输入到分配)。

## 按截图生成一份计划

1. 在“任务描述”里写清任务。粘贴很长的三分钟科幻短片提案也能规划，但长文里的背景、宣传语、例子可能被当成需求。想得到可执行的分工，建议改成下面这种**有编号的交付项**。
2. 只想推荐一个模型时选**单任务**；需要独立交付物、依赖和验收时选**团队分工**。长篇复合项目可以先选团队分工。团队规划对显式执行项有数量上限，过多的条目可能被合并，因此把最重要的任务列在前面。
3. 预算先填 `0`，看无预算约束时的推荐；填入自己接受的估算金额后重新生成，比较路线变化。预算仅参与排序，不会阻止工具、厂商或账号继续扣费。
4. 点**生成路由建议**，向下滚动，越过“逐模型价格与能力”卡片，找到**路由建议**。修改任务、模式、预算或档案后，旧结果会消失或不再适用，需要重新生成。
5. 查看“推荐路线”“任务复杂度”“估算总成本”和“执行渠道”。`价格待配置` 表示缺少可用单价；`官方 CLI` 表示该供应商工具在当前环境已有可托管的执行入口；`模型目录 API` 表示可通过 Harness 模型目录调用，但并不代表 CLI 团队执行器会运行它。
6. 在团队结果里逐条查看**工作包的具体目标、难度、推荐路线、依赖、估价、验收与执行渠道**。如果出现“预算可能超过”“质量约束放宽”“图像工作包无法分配”等提示，先修正模型配置或任务描述，不要把计划当成已完成交付。

一个适合当前短片提案的**规划输入示例**：

```text
目标：为一部 3 分钟科幻短片制定制作计划。当前只需计划和文字/代码交付，不要声称已生成成片。
1. 将故事压缩为 3 分钟结构，交付场景顺序与约 12 个镜头的分镜文字表。
2. 列出角色、场景、声音、字幕所需资产及命名规则，标注可复用项。
3. 为项目仓库设计素材清单和构建/验收脚本，说明依赖哪些图像、音频与剪辑软件。
4. 核查镜头时长、素材版权、字幕与输出格式，列出尚需人工确认的事项。
验收：每项都有文件名、输入、输出与检查方法；不足的信息明确标记为待确认。
```

这段文本可帮助路由器把提案变成可审阅的工作包。**生成路线建议只生成计划**；它既不会调用 Blender、ComfyUI、DaVinci Resolve 等创作软件，也不会自动生成视频文件。当前托管执行器面向注册表中的官方模型编程 CLI。短片的真实画面、配音、剪辑和渲染仍要在相应工具中制作并验收；不要把“建议路线”理解为“短片已制作完成”。

## 什么时候会真正调用模型或工具？

工作台按钮止于**本地规划**。要进行真实调用，请在 Harness 左侧点**新会话**，选择正确的工作区，并明确让会话使用插件工具。推荐先做一轮只读核对，再考虑可编辑执行。

| 想做什么 | 在官方会话中明确请求 | 结果与前提 |
| --- | --- | --- |
| 再看一次可审阅计划 | “请调用 `model_router_plan`，对下面的任务按 `team` 模式规划，预算估值 10 USD，先不要执行。” | 返回计划；不代表任务已执行。 |
| 让另一个已配置模型给意见 | “请调用 `model_router_consult`，让已配置模型评审这份分镜文字，只返回问题与改进建议。” | 真正调用 Harness 模型，可能计费；可以指定目录中准确的 `provider` 和 `model`。 |
| 检查 CLI 安装 | “请调用 `model_router_tools`，列出各官方工具的安装和执行入口状态。” | 只做检测，不登录账号。 |
| 让某个官方 CLI 做一项任务 | “请调用 `model_router_tool_run`，用 `codex` 以 `read-only` 模式检查仓库里的分镜清单和脚本，并列出问题。” | 需要该 CLI 已安装、入口就绪、厂商账号可用。只读模式不应修改项目。 |
| 按依赖执行多个工作包 | “请先规划并展示工作包；我确认后请调用 `model_router_team_execute`，以 `read-only` 模式执行下面列出的项目检查任务。” | 重新基于**当前可执行 CLI**规划并顺序执行；结果可能与工作台卡片的推荐不同。 |

### 会话工具的参数长什么样

这些 JSON 是**核对 Agent 工具调用的示例**，不需要粘贴到工作台的“任务描述”框。在官方会话里用上表的自然语言请求即可；若会话展示工具调用详情，可对照参数：

```json
{"task":"检查短片项目需求并分工，交付分镜文字和验收清单","mode":"team","budgetUsd":10}
```

上面是 `model_router_plan` 的参数，只生成本地计划。要让一件已安装的官方 CLI 做只读检查，`model_router_tool_run` 可使用：

```json
{"tool":"codex","task":"检查当前仓库的分镜清单和构建脚本，列出缺失与风险；不要改文件","mode":"read-only"}
```

需要多包真实执行时，`model_router_team_execute` 的基本参数为：

```json
{"task":"检查分镜时长、资产清单和构建脚本，逐包交付问题清单","mode":"read-only","budgetUsd":10}
```

`tool` 必须是固定 ID：`kimi-code`、`claude-code`、`codex`、`minimax-code`、`mimo-code`、`grok-build` 或 `zcode`。单工具调用若要指定厂商 CLI 的准确模型名，需同时给出官方目录中成对的 `provider`、`model` 和可选 `cliModel`；MiniMax/MiMo 的 `cliModel` 为 `provider/model` 格式。不要猜 CLI 模型名。团队工具可用字符串参数 `cliModelsJson` 为工具或工作包指定已在厂商 CLI 验证的名称；ZCode 3.14.3 无逐次换模型功能。

若希望 CLI 修改文件，将执行模式指定为 `workspace-write`，先在**干净的测试 Git 仓库**运行，并经过 Harness 的工具审批。编辑工作会在隔离 Git worktree 中进行；执行失败会停下，不应直接承诺结果已经整合。当前 Claude、Codex、MiMo、Grok 可申请只读或可编辑执行；Kimi、MiniMax、ZCode 的托管执行只支持经审批的可编辑模式。不要用尚未准备好的真实素材仓库作为第一次试运行目标。

`model_router_team_execute` 不会简单照抄工作台已经显示的卡片：它按当前**已配置、已安装、入口就绪、支持所选模式**的 CLI 路线重新规划。工作台的 `模型目录 API` 路线不会自动变成该工具中的 CLI 工作包。ZCode 3.14.3 使用其自身默认模型；其他厂商的 Harness `provider/model` 和 CLI 名称也可能不同。CLI 模型名只在确认厂商工具接受该名称后填写；多数 CLI 不回报可核验的实际模型 ID，执行后要对照厂商运行记录。

## 官方工具卡片怎么用

向下滚动到**官方工具**，先点**重新检测**。每张卡片有工具 ID、探测版本、目标版本、执行入口说明和操作按钮：

![0.9.0 隔离验证环境中的官方工具卡片](assets/desktop-official-tools-0.9.0.png)

*图为隔离验证环境的桌面实拍；图中的安装状态不代表你的账号状态。*

1. 显示“未安装”时点**下载安装**；ZCode 显示**下载安装器**，下载并打开厂商安装窗口后，还需在窗口中选目录完成安装，再回到工作台点**重新检测**。
2. 安装中可看**安装日志**，需要中止时点**取消安装**。取消后点**重新检测**确认实际状态。
3. 显示“已安装”但说明“当前不可托管执行”时，看原因；目标版本正确却缺少可信入口时可点**修复官方执行入口**。若显示**请人工核对版本**，先核对本机已有版本和来源，不要把无法核验的入口当作可执行。
4. 显示“官方执行入口已核验”后，再到相应厂商完成登录或授权，并在小任务上检验模型权限。**安装成功、执行入口就绪和账号可用是三件不同的事。**

前六家 CLI 的下载安装使用插件固定的 npm 包和版本。若不希望占用 C 盘，先核对系统 npm 全局安装前缀的位置；ZCode 的原厂安装窗口可选择目录。卡片不会接受自定义包名或任意命令。

## 常见情况

| 看到的情况 | 先检查什么 |
| --- | --- |
| “生成路由建议”按钮不可点 | 等目录及官方工具检测完成；若右侧没有路线，先去 Harness 官方“模型”页配置，再点“刷新”。 |
| 点了按钮但看不到结果 | 向下滚动到“逐模型价格与能力”之后的“路由建议”；若有红色错误，按错误提示修正任务或预算。 |
| 显示 `价格待配置` | 为实际比较的每条路线同时填写输入/输出 USD 单价并保存，再重新生成；未知价格就保持未知。 |
| 推荐了不希望使用的模型 | 核对它是否在官方目录、质量与价格是不是你填的、擅长标签和预算是否合适；更改后重新生成。目录中的路线不代表账号有权使用。 |
| 工作台写“官方 CLI”，会话执行却失败 | 查看工具卡片的入口状态，检查 CLI 登录、厂商权限、网络和所选模式；再检查 Harness 会话工作区与审批结果。 |
| 工作台规划与团队执行选的模型不同 | 团队执行会按当前可运行 CLI 与执行模式重新筛选。若 CLI 模型名需要不同于目录 ID，先在厂商 CLI 核实，再设置对应映射。 |
| 会话里找不到 `model_router_*` 工具 | 确认插件安装且已启用；在新会话中检查工具是否可用，并记录插件详情及脱敏错误日志。 |
| 预算显示超出或实际账单更高 | 预算仅影响本地估算；对照实际输入/输出 token、缓存、重试和厂商单价，在厂商侧管理真实消费。 |

若要反馈问题，请附 **Harness 桌面版版本、插件版本、脱敏后的错误文本、工具卡片状态、选择的模式**，不要附密钥。源码里的路由规则和估价假设见 [中文 README](../README.zh.md)；安装和版本排障见[安装与验证指南](../INSTALLATION_GUIDE.zh.md)。
