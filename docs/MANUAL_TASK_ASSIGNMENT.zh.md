# 选择算法分配或手动调整

在工作台生成路由建议后，可以选择 **按算法推荐分配**，也可以选择 **手动调整分配**。

1. 输入任务，选择“团队分工”，生成路由建议。单任务也可以调整一个工作包；“指定模型”沿用原来的全局模型选择。
2. 使用算法分配时，工作包按推荐方案和已设置的计费策略执行。
3. 切换到手动调整后，每个工作包都有独立的目标选择。初始选择为该包的推荐模型 API，可改成其他已配置的模型 API，或者已安装且支持只读执行的官方工具。
4. 核对任务目标、前置依赖、原算法推荐与新选择。修改目标不会改变任务拆分和依赖关系。恢复推荐可重新填入各包的推荐模型；切回算法分配会恢复原有自动策略。
5. 点击“预览执行计划”，核对 Host 验证后的实际目标、费用和权限，再确认执行。修改任务、模型目录、设置、规划依据或分配选择后，需要重新预览。

手动分配支持在一次运行中混合模型 API 与官方工具，例如由模型分析、Codex 检查、另一个模型汇总。各包按依赖执行，上游失败会阻止依赖它的后续工作包。结果和分配选择保存在同一份运行记录中，失败步骤重跑沿用保存的目标；改派重跑则使用新选择。

## 模型和工具分别代表什么

- **模型 API**：固定调用所选 provider/model，使用适配器默认推理档位。不会因为 CLI 已安装、订阅优先、质量升级或自动省钱策略而改为其他模型或渠道。配置为只用订阅的路线，以及编程套餐专用端点，不能直接作为普通 API 目标；预览会说明原因。
- **官方工具**：固定调用所选的注册工具，使用该工具自身配置的默认模型。选择工具不等于选择某个 API 模型；如需控制工具内部模型，应在该官方工具的配置中设置。未安装、平台不支持或执行未就绪时，预览会拒绝执行；工具失败不会自动转 API。

工具默认模型的价格通常无法可靠预估，因此显示“价格待配置/费用未知”，不会套用原推荐 API 模型的价格。已报告的真实费用仍按现有账本规则记录。预算 0 表示未设置本次估算上限；有限预算下，手动目标费用过高或无法确认满足本次预算时会暂停，确认后仍沿用手选目标，不会自动换成便宜模型。估算不是厂商实际扣费的硬上限。

手动混合分配当前执行只读任务。需要编辑工程文件时，继续使用“官方工具协作 → 编辑文件”的隔离工作树流程。该流程保留现有权限确认与改动整合机制。

如果“允许手动改派”设置关闭，工作台也会关闭手动分配入口。

## 在官方会话工具中使用

先调用 `model_router_plan`，保存返回的 `packagePlanKey` 和 `team.workPackages`。再调用 `model_router_execute`，使用相同的任务文本与规划模式，传入：

```json
{
  "assignmentMode": "manual",
  "packagePlanKey": "复制当前计划返回的键",
  "packageAssignmentsJson": "以当前计划全部工作包 ID 为键的 JSON 对象"
}
```

每个绑定只能是下面两种结构之一：

```json
{ "kind": "api", "provider": "目录中的供应商 ID", "model": "目录中的准确模型 ID" }
```

```json
{ "kind": "tool", "toolId": "codex" }
```

必须覆盖当前计划中的全部工作包，不可添加其他包 ID。拆分键过期、目标不存在或后续工具未就绪时，会在第一个模型调用前拒绝整次执行。未传手动分配参数时，工具继续使用算法推荐。
