# Windows 电脑、Bot 路由与例行任务使用指南

适用于 **0.63.0 正式版**，2026-11-05。远程电脑 Agent 自身版本为 **0.1.0**，与插件版本独立。

本指南描述当前可操作工作流。它不提供云电脑购买、VM 自动创建、云账单代管或本产品自有 iOS 客户端，也不声称完整复刻 Grok 的商业服务。Grok 公开工作流来源和本轮官网重访受 Cloudflare 阻挡的记录，见[能力映射与边界](implementation/20261105-grok-workflows.md)。

## 先准备什么

| 所在位置 | 准备内容 |
| --- | --- |
| Harness 电脑 | 安装已核验的本地插件构建，启用后连同托盘一起退出并重启；配置可用的 Provider、模型及协调用 Main Bot。 |
| 被控 Windows/云电脑 | 自己准备的 Windows x64 电脑；已登录且可用的交互桌面；完整 Agent zip。 |
| 两台电脑之间 | 已配置并能互通的 WireGuard/Tailscale 私网，或受保护隧道。配对文件不会替你建立网络。 |
| Bot 设置 | 各 Bot 的准确模型、工具、工作目录和必要机器授权。角色简报不等于工具授权。 |

安装插件的核心步骤也在双语根 [README](../README.zh.md) 中，以便代码与 README 分发独立使用。这里不要求修改用户数据库或手工编辑 Host 凭据存储。

## 在 Windows/云电脑运行安装向导

1. 将完整的 `DSH-RemoteAgent-windows-x64-…zip` 解压到长期保留的目录。完整包包含普通 Node、生产依赖、`dist`、`start.cmd`、PowerShell 安装/启动脚本及 native helpers；不要只复制一个 exe 或 `start.cmd`。
2. 登录该电脑的 Windows 桌面，双击 **`start.cmd`**。向导默认寻找包内 Node；完整包无需再单独从源码安装 Node 模块。
3. 选择安装目录和 **workspace**。workspace 是允许 Bot 处理文件的远端工作目录，例如 `D:\DSH-Workspace`；它会通过 `project` 这样的 root ID 对 Host 暴露。
4. 填写 **bindAddress**：一个实际存在的本机/私有 VPN IP。默认 `127.0.0.1` 只用于本机或另行配置的端口转发；不要填写 `0.0.0.0`。
5. 非回环地址需要确认 **protectedTunnel**。只有地址已经位于你配置的 WireGuard/Tailscale 私网时才确认。端口默认 `9701`。
6. 填写 **endpoint**：Harness 电脑实际能够访问的 Agent 基础 URL，例如 `http://10.42.0.2:9701`。不带 `/mcp`、账号、查询参数或片段；通过代理时填写实际代理地址，并按网络部署说明配置保护。
7. 决定是否开启 **hostManagedBots**。选择开启，表示明确信任这个已认证 Host 在配对目录/工具上限内管理现有和新建团队 Bot。选择关闭，则填写固定允许的 Bot ID；新 Bot 不会自动进入固定名单。
8. 选择可选的命令执行和浏览器权限。命令以该 Windows 用户的权限执行；不需要的能力可以不开启。浏览器 origin 留空时不启用相应网站导航权限。
9. 等待向导完成，记下它显示的安装目录、任务名称和 **`private/pairing.private.json`** 路径。

向导为当前用户注册 Agent 与桌面 helper 两个任务，使用交互登录令牌和普通权限，不保存 Windows 密码；Agent 在后台运行，helper 使用明确的 full-desktop 模式。画面和输入依赖已登录用户的桌面，不能将“任务在运行”视为锁屏、安全桌面或任意会话都能采集的保证。

再次运行向导会保留已有配置和凭据。为另一套配置使用另一个空安装目录及对应任务名；不要覆盖已有私有配置来排除连接问题。

`hostManagedBots` 只在本地管理员配置/配对时启用。普通 grant 请求和模型参数不能开启它，root/tool 上限、Bot ID 校验、撤销与客户端版本仍有效。

## 将电脑配对到 Harness

1. 从被控电脑安装目录，将 **`private/pairing.private.json`** 私下转移到 Harness 电脑。
2. 在产品 **远程电脑 → 添加电脑** 中选择/导入该文件。导入自动填写 endpoint、machine/client 标识、`rootIds`、工具列表、私网隧道和团队 Bot 管理标记。
3. 核对地址与目录列表，选择表单要求的 Bot，提交配对并探测。不要用被遮蔽的 token 占位符替代原文件，也不需要把密钥逐项复制到表单外。
4. 在 **Bot 绑定** 和机器授权中检查 Main/执行 Bot 的实际权限。观看需要截图；接管及 routine 回放还需要相应桌面输入工具和写模式。
5. 核对实际机器状态。Agent 在线只证明控制面可访问；桌面 helper、用户会话、浏览器和可选命令能力分别有自己的可用条件。

配对文件包含 Host 的长期配对凭据。它不应上传 Git、贴到问题报告或交给模型。浏览器桌面页面只接收短期会话 ticket；配对凭据和 Agent grant 由 Host 保管。

目录授权使用 root ID。例如 `project` 对应安装时选的 workspace，后续请求只能在已提交的目录和工具上限内操作，不能靠给模型一个本机路径扩大权限。

## 观看、接管、归还和放大

1. 打开某个 Bot 右侧的 **电脑操作** 页签，或进入 **远程电脑** 页面中的桌面区域。
2. 选择这个 Bot 已有权限的电脑；有多个显示器时选择目标显示器，点击 **连接桌面**。
3. 默认 **仅观看**。画面是整台电脑所选屏幕的实际桌面，而非只显示某个浏览器标签。
4. 点击 **取得控制权**，等状态显示你正在控制后再操作。键盘、鼠标、滚轮、粘贴或文字发送会经原生端确认；中文/多行文字可使用文字发送框。
5. 真人取得控制权后，冲突的 Bot 桌面输入会被阻止。点击 **仅观看** 归还控制并释放已按住的按键/鼠标按钮，再让 Bot 继续自动化。
6. 点击 **放大**，或在观看模式双击，进入铺满应用的放大查看界面；**关闭放大** 返回小面板。放大是应用内查看方式，不改变远端分辨率。
7. 完成后点击 **断开**。如果提示远端释放尚未确认，去真实电脑检查，不能将关闭本地画面等同于确认停止远端输入。

实现链路为 **Windows GDI → JPEG → WebSocket**，带 grant 续期、控制权与逐输入 ACK。这是独立实现，不使用 RustDesk 协议；没有承诺已达到 RustDesk 性能或固定 30 FPS。以当前界面显示的实测分辨率/FPS 为准，网络、屏幕大小及解码都会影响结果。更完整的原生与传输验证范围见[桌面引擎记录](implementation/20261105-desktop-engine.md)。

## 演示一次并保存例行任务

1. 连接桌面并取得控制权，把应用恢复到明确的起始页面。
2. 输入例行任务名称，点击 **开始录制**，像平常一样演示。
3. 录制器只收集这个桌面会话成功 ACK 的输入。连续 pointer move 以 **200 毫秒** 时间桶保留路径点和动作前最终位置；按钮、按键、文字、滚轮的顺序不丢失。
4. 点击 **结束并保存**，等待队列排空、释放按住输入和 Host 保存确认。保存的文字属于 routine 内容；涉及账号输入时要明确知道所录文字也会保留。
5. 只有 Host 返回与草稿一致的已保存记录才显示成功。没有确认时草稿保留，可以先查看例行任务列表确认是否已保存，再单独重试保存；不会因此重做桌面动作。
6. 在 **例行任务** 页面选择同一 Bot、目标电脑，先手动恢复起始页面，再点击运行。

边界：最多 **200 个采样后步骤**，单次停顿不超过 **60 秒**；不可合并的输入超过 200 会使整段录制无效，不截断后伪装成功。回放必须匹配录制时的显示器 ID、物理尺寸、坐标系和已录 DPI。按钮移位、页面切换或应用状态变化仍需要重新演示，鼠标采样不适合精细绘图。

这不是通用视觉学习。成功只表示输入执行与清理得到确认，业务结果还需要验收。回放会取得控制权、逐条等待 ACK、续期授权，完成/失败/取消时释放输入、归还控制并关闭会话。

## 处理失败和 unknown

| 结果 | 含义与操作 |
| --- | --- |
| succeeded | 所有记录动作得到 ACK，清理得到确认；继续检查业务产物是否符合要求。 |
| failed | 明确拒绝或失败，后续步骤未继续；查看停止位置并修复起始状态。 |
| cancelled | 在已确认动作之间停止，并完成清理；之前已发生的动作不会撤销。 |
| unknown | 已发送输入的 ACK 丢失、断线、Host 中断，或清理/关闭未获确认；可能已生效，禁止盲目重跑。 |

同一 Bot/电脑有未核对 unknown 时，不允许开始另一段 routine。先查看真实电脑和执行记录，确认工作做到哪里，恢复适合后续运行的界面，然后在 **执行记录** 填写检查说明并解除阻塞。旧 unknown 仍保留为 unknown，不改写成成功，也不自动重放。

请求停止不是确认停止。Host 退出时会禁止新 routine、取消活动 routine，并等待原生释放和最终日志；异常断电/进程中断无法凭空补出确认，恢复后仍需检查。不要删除执行账本来绕过这个步骤。

## 配置并使用 Bot 路由

1. 在 Harness 模型页面配置路线，在各 Bot 设置/绑定中选择准确模型、工具、工作区和机器权限。Main、写代码、浏览器等 Bot 可以有不同配置。
2. 在 **任务 → Bot 路由** 开启功能，选择 **省钱优先 / 均衡 / 效果优先**。候选表读取已提交状态，显示模型、机器、价格/质量证据和忙闲情况。
3. 输入可验收任务。选 **自动路由**，或指定某个 Bot；如需电脑，选择机器/root 和实际需要的只读、写入、桌面或浏览器能力。
4. 点击 **预览路由**，检查选中者、落选原因和拟新增机器绑定。可选 **自动授予任务所需电脑权限** 受机器 ceiling 和 Main 可委派范围限制，不是任意授予系统权限。
5. 点击 **按此路由创建任务** 才真正派发。查看任务状态、执行过程和结果；计划受理不等于执行完成。
6. 向 Main Bot 发消息时，可让它用 `bot_route_task` 或 `bot_dispatch` 分配任务。两者默认真实派发；需要只看决定时明确 `preview:true`。

示例：让 Main 先预览“把当前发布记录整理为待核对清单”，检查候选后再派发。Main 的工具调用身份来自实际会话，工作 Bot 使用自己的准确绑定和私有工作环境，模型不能靠参数冒充另一个 Bot。

当前真实 SDK 0.2.1-rc.4 已走通 Main 工具 → 路由执行 Bot AgentLoop → 私有资料库写入 → task succeeded。执行 Bot 后续每次模型请求独立做预算准入并关联父任务；这段证据不是所有 Host/浏览器探针、厂商账户或云电脑场景都已通过的声明。

## 使用 Bot 私有资料库

1. 打开 **资料库**，选择 Bot。
2. 进入或新建文件夹，上传本地文件；二进制上传/下载每文件最多 **16 MiB**，下载保持原始字节。
3. 打开支持的文本文件进行编辑，或新建文本；文本读/写每文件最多 **1 MiB**。打开已有文本后点击保存会更新内容；同名文件上传会被拒绝。
4. 页面名称输入框筛选当前目录；正文检索时，在 **搜索这个 Bot 的文本内容** 中输入查询并点 **搜索文本**。结果显示路径、行号和片段，点击路径可打开对应文件并选中匹配行，编辑后仍保存到原来的完整路径。
5. 搜索不区分大小写，按字面匹配而非正则表达式；查询最多 256 字符，最多扫描 500 条目/8 层目录，返回最多 50 个匹配行，仅限不超过 1 MiB 的支持文本。获准的 `bot_library_search` 使用同一后端，并核对实际调用 Bot 私有库。二进制文件可以保存/下载，但上传不代表已经 OCR、提取全文或建立语义向量索引。
6. 让 Bot 使用自己已授权的资料库工具处理文件。资料库按 Bot 隔离，不是远端 workspace，也不是上游头像库。

## 常见排查

| 问题 | 优先检查 |
| --- | --- |
| 解压后双击提示缺少 Node/helper | 是否解压完整 Agent 包，目录结构和生产依赖是否保留。 |
| endpoint 无法连接 | URL/端口是否从 Host 可达，VPN/端口转发是否已配置，监听地址是否属于被控电脑。 |
| Agent 在线而画面不可用 | 当前用户是否保持登录，桌面 helper 任务是否在该交互会话，full-desktop 模式是否正确。 |
| 没有接管权限 | Bot 截图/输入工具、写模式授权及其他会话控制权占用。 |
| 新 Bot 被机器拒绝 | 配对是否使用固定 Bot ID；未开启 hostManagedBots 时不会自动接受新 ID。 |
| 路由无候选 | 预览落选原因、准确模型、所需工具、机器/root、忙闲和预算条件。 |
| `TOOL_DENIED` | 实际已提交工具名/授权与请求是否一致，不把角色提示词或预览结果当成权限。 |
| Routine 很快停止 | 显示器/DPI、应用起始状态、步骤上限、ACK 和停止位置。 |
| 点击保存没有确认 | 保留草稿，刷新列表核对是否已保存，再决定是否单独重试保存。 |
| 更新后仍旧界面 | 退出托盘和 Host 后重启，并检查真正加载的本地包路径/版本。 |

## 来源与维护

DS Bot 运行时固定为 0.2.7，提交 `71d344bf193f3f18185f25de3d8e5c483046910a`，352 个上游原始文件、6个产品覆盖文件（总361文件，含许可与生成客户端）。产品覆盖层外置，不能直接改 vendor；具体导入/校验命令见根 README 和 AGENTS。上游包含群聊、长期上下文、own/group/team 记忆、学习提议、浏览器、Office 预览、头像库等；完整桌面和文档文件资料库由本产品实现。

Windows Agent 完整包可通过仓库的 `scripts/package-remote-agent.ps1` 构建；脚本不会创建 VM、部署到用户电脑或替用户开启向导。验收时应区分本地 fixture、真实 SDK Host、Windows native、真实网络与真实业务结果，避免将某一项通过扩大为整体商业服务对等。


本轮实测：Harness 0.2.2-rc.1 的50项完整离线Host验收通过，真实Chromium页面/资料上传搜索与桌面画面均通过。10.0.0.2的1920×1080桌面在当前WireGuard链路8秒样本约13.12FPS，16次输入确认p50为125ms、p95为274ms；不是固定帧率承诺。已有9701 Agent已备份升级并保留原机器ID、凭据与配置。
