## 实施记录

### 1. 空会话崩溃修复

根因是会话初始化阶段的 `legacy.nodes` 可能暂时为 `undefined`，而路由恢复、台词转换和协作面板仍会直接访问节点数组。

处理方式：

1. 在 `client/transcript.mjs` 增加 `normalizeNodes()`，把无效节点值转换为稳定的空数组。
2. `GalView.jsx` 的会话数据入口统一归一化节点，所有下游逻辑只处理数组。
3. `nodesToLines()` 复用同一归一化规则。
4. 增加 `undefined`、`null` 和稳定空数组引用的回归测试。

### 2. GAL 数据源和发送管线修复

`GalView` 改为从宿主 `useChat().legacy` 读取节点、流式内容、运行调用和状态；`useSession` 只读取生命周期状态。发送仍通过宿主 `inputActions.submit()`，保证与普通对话输入使用同一条管线。

同时修复 GAL 草稿与宿主草稿的异步回写竞态：

- 发送前同步宿主草稿。
- 发送后立即清空本地草稿。
- 只有宿主确认写入了同一个值后，才允许外部草稿状态回写本地输入框。

### 8. GAL 输入框卡顿与光标跳动优化

用户反馈在 GAL 输入框中连续输入时文字顺序反转、光标不断跳回开头，无法流畅编辑。

根因是 GAL 每次 `onChange` 都调用宿主 `inputActions.setDraft()`。Harness 的 `setDraft()` 会清空并重建 Lexical 编辑器树，再把宿主选区移动到文末；逐键调用会触发全局输入状态更新和 GAL 重渲染，导致 textarea 的 DOM 光标被重置。

处理方式：

1. 逐键输入只更新 GAL 本地 React 草稿，不再重建宿主 Lexical 树。
2. 在提交前、输入框失焦、组件卸载/会话切换和路由模式命令提交时同步宿主草稿。
3. `useInput` 只订阅 `draft` 与 `imageIds`，忽略队列、阶段和通知等无关状态变化。
4. 输入框获得焦点时不接受外部草稿覆盖；提交后本地草稿为空时允许宿主恢复失败提交的原文。
5. 记录 `selectionStart`、`selectionEnd` 和方向，并在布局更新后恢复选区，保证中间编辑和连续输入都不跳光标。
