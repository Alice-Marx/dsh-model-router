# 0.25.4 release acceptance

Date: 2026-10-26. Package: `@ljwei-stak/dsh-model-router@0.25.4`.

## Behavior

Windows npm installation now handles the three observed legacy ZCode desktop
launcher templates occupying its selected prefix. It scans all command files
before moving anything, recognizes complete fixed-path templates only, and
preserves their original bytes in a unique `.zcode-legacy-shims-*` directory
with a hash manifest. The install log records that directory before npm runs.

Failure, cancellation or failed verification restores missing old launchers
without overwriting new npm or user files. Backups remain available after
success and rollback. Unknown files, mismatched desktop targets, command links
and linked prefix ancestors are not migrated. No `--force` is added. Existing
desktop resources, configuration, login and sessions are preserved.

## Validation

- Pinned frozen pnpm installation with strict peer dependencies passed.
- Complete local regression suite: 1,230 tests, 1,227 passed, 0 failed and
  3 environment skips on Windows / Node 24.20.0. Actual Desktop client rebuild
  (980,828 bytes), client check, bilingual README pairing and offline preview
  compilation passed.
- Eleven focused migration regressions cover complete template recognition,
  BOM/CRLF bytes, shell metacharacters, backup preservation, exclusive rollback,
  existing npm/user files, mixed collisions, links/junctions, repeated attempts,
  mismatched desktop targets, cancellation and changed backup bytes.
- Actual Windows repair identified and backed up all three legacy launchers,
  then installed the published `@ljwei-stak/zcode-cli@3.16.2` into the same npm
  prefix. npm registry attestation, complete runtime verification, version
  output, terminal entry selection and managed readiness passed. No model
  request was made; private machine paths and logs are kept in the dated export.
- Publication is gated on Windows/Linux CI and npm archive verification against
  committed Git bytes and the runtime import closure. Exact CI references,
  archive counts, digests and anonymous npm/GitHub download verification are
  retained in release notes and the dated export evidence.

The local repair verifies the actual installation and launch path. It does not
claim a new installed-Desktop UI end-to-end run or new paid vendor inference.
