# 0.25.5 acceptance report

The reported ZCode TUI corruption was reproduced with the published ZCode
3.16.2 runtime and the router's actual Windows ConPTY dependency. UTF-8 native
output was interpreted with the console's legacy code page before it reached
xterm.js, damaging box drawing and some adjacent VT sequences. Starting Node
inside a UTF-8 console restores that output; a preload after Node startup did
not resolve the issue and is not used.

## Change

Only Windows ZCode PTY launches use a profile-free PowerShell bootstrap. It
sets that new console's input/output encoding to UTF-8, runs the already
verified Node/runtime entry with literal arguments, and forwards its exit
status. No system, registry, user profile, npm package or global console
setting is changed. Both npm and GitHub Release selections use this path.
Other tools, POSIX launches and pipe fallback retain their existing behavior.

## Evidence

- Actual router `CliTerminalCard`, `TerminalConnection`, session manager and
  Windows ConPTY rendered the published ZCode 3.16.2 TUI in a local browser.
  The logo, box drawing, colors and Chinese draft input were inspected. At
  a 960-pixel viewport the TUI redrew to the narrower terminal. Ctrl+C input
  ended the real session and the UI reported exit code 0. The draft was not
  submitted; no model was called.
- `node scripts/check-terminal-utf8.mjs` uses native file-descriptor output,
  truecolor VT, a Unicode path containing spaces, apostrophes, ampersands and
  `%PATH%`, Unicode keyboard input, resize and an exit-7 fixture. It verifies
  the real process handle's exit status and cleanup, without a vendor CLI or
  network. The Windows CI job runs this regression explicitly.
- Terminal unit/gateway tests cover the fixed launch marker, literal quoting
  and unchanged POSIX/non-ZCode behavior. Full-suite, frozen dependency graph,
  generated client and package-byte checks gate publication. Exact results,
  CI references and registry digests are retained in release notes/exports.

This is a real native PTY and real client-component validation in an isolated
local harness. It does not claim a new installed-Desktop application run,
vendor login or paid model inference. The standalone ZCode npm package remains
3.16.2 because the defect and fix are in the router's Windows terminal host.
