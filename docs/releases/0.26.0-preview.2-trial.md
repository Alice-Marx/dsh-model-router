# 0.26.0-preview.2 — rc.5 isolated trial / rc.5 隔离试用

## What changes / 本次变更

This preview fixes a real compatibility rejection: rc.5 refuses preview.1 before plugin code loads. Preview.2 adds only the exact `0.2.1-rc.5` peer version and pins its source-build SDK to rc.5. It does not weaken the Host gate, grant an exemption or silently replace preview.1. The original integrated product scope and all incomplete acceptance gates remain unchanged.

本次修复 rc.5 在插件加载前拒绝 preview.1 的兼容性缺陷：仅新增精确的 `0.2.1-rc.5` peer 版本，源码构建 SDK 固定到 rc.5。不修改 Host 门禁、不授予版本豁免、不覆盖 preview.1；原一体化产品范围和未完成验收均保留。

## Install / 安装

Publication is established by the actual registry entry and GitHub prerelease, not this guide. Use only an independent disposable test home/profile. Back up data and fully quit your own test Desktop before changing its installation. Do not point it at production Bot, Session, workspace, funding, CLI or remote-machine data.

是否已发布以实际 npm 条目和 GitHub prerelease 为准，本文不是发布收据。仅使用独立、可丢弃的测试 home/profile；先备份数据，安装前自行完全退出该测试 Desktop。不要指向生产 Bot、Session、工作区、资金、CLI 或远程机器数据。

- In the isolated **Harness Desktop 0.2.1-rc.5 → Plugins → Add plugin**, enter `@ljwei-stak/dsh-model-router@0.26.0-preview.2`; restart that test instance.
- 在隔离 **Harness Desktop 0.2.1-rc.5 → 插件 → 添加插件** 中输入 `@ljwei-stak/dsh-model-router@0.26.0-preview.2`，然后重启该测试实例。
- Use exact version `0.26.0-preview.2` or the verified npm `preview` tag, never stable `latest`. A global `npm install -g` does not register a Desktop plugin. Do not use `dsh plugin allow-version` to force preview.1 onto rc.5.
- 使用精确版本或经核对的 `preview` 通道；稳定 `latest` 不作为试用通道。全局 npm 安装不等于 Desktop 插件注册，也不要通过版本豁免强行加载 preview.1。
- Use CLI installation only when the Desktop-provided CLI is positively bound to this disposable initialized Desktop profile; do not run a generic npm CLI against your normal `desktop` profile.
- CLI 安装必须确认命令来自该测试 Desktop，且目标是已初始化的可丢弃 profile；不要用通用 npm CLI 操作日常 `desktop` 配置。

## Try first / 建议先试

1. Check that DS Bot + Model Router loads, inspect the Main Bot and unified navigation, then restart the disposable instance and check that its identity persists.
2. Inspect exact-model settings, route previews, task plans and separate API/subscription accounting. These checks need no real inference.
3. If you personally choose real execution, configure credentials and explicit permissions in that test instance and set your own budget. It may incur charges and access the selected workspace. This release does not verify your account, login, tool or model.
4. Report exact plugin/Host/Node/OS versions, install path type, minimal steps and redacted errors. Never attach credentials, tokens, private Session/funding data or the whole test home.

先检查一体化界面、Main Bot、导航和重启后身份，再看精确模型设置、路由预览、任务计划与 API/订阅分账；这些检查不需要真实推理。用户自行选择真实执行时，应在测试实例配置凭据、权限与预算，可能产生费用或访问工作区。本次不证明真实账号/登录/工具/模型可用。反馈版本、安装方式和脱敏最小复现，不上传整份 home、密钥或私人会话/资金数据。

## Known limits / 已知限制

- rc.5 compatibility has bounded offline evidence, not clean installed-Desktop/full product acceptance. Exact results and failed runs are listed in the [validation report](0.26.0-preview.2-validation.md).
- rc.5 兼容验证有明确的离线边界，不等于全新 Desktop 安装或完整产品验收；失败和实际通过范围见验证报告。
- Formal status remains **0/20 work packages, 44/63 scenarios, M0 11/12, G1–G4 in progress**. All 40 feature rows retain `behaviorVerified=false`; C1–C10 and production activation/stop-write/post-activation rollback remain closed.
- 正式状态、完整迁移和生产安全门禁未提升。source-only 诊断不等于包内完整迁移能力；不要对真实数据运行仓库迁移脚本。
- Lifecycle-disabled dependency installation and an existing SQLite prebuild loading are not strict clean native installation. Hosted CI, complete OS/DPI/UAC/RDP/tool/login/vendor matrices, real remote topology, long-duration performance and deployment remain separate unfinished items.
- 跳过生命周期脚本、既有 SQLite 预编译件加载不等于完整原生安装；hosted CI、平台/物理桌面/工具/账号/真实远程/长跑/部署仍未全部验证。不得关 TLS 校验、修改系统编译器或真实账户绕过。

## Recovery / 恢复

Stop and remove only the disposable test installation/profile. Keep production data and original backups untouched. Reinstalling stable 0.25.5 is not a data-schema downgrade or accepted post-activation rollback; never let an old release read data modified by a newer test release.

停止并移除可丢弃的测试实例；不要改生产数据或备份。重装稳定版不等于格式降级或已验回滚，不让旧版读取新版试用修改的数据。

The [detailed unfinished-work register](0.26.0-preview.2-unfinished-work.zh.md) records task impact, failures/skips, blockers, prerequisites and next actions. Partial, skipped, timed-out and unknown results are not passes.

详细未完成工作文档逐项记录影响、失败/跳过证据、阻碍、完成条件与后续步骤；部分完成、跳过、超时或未知不记通过。
