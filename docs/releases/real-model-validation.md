# 更新后的真实模型验收

每次修复或更新后，在实际 Harness 中加载本次构建的候选版本，用已配置的真实模型逐条验收。使用测试 Bot、测试群和临时工作目录，发送简短且不含个人信息的提示词。

1. 对每条已配置的模型路线，从 DSH Bot 新会话发出一条消息。核对实际使用的提供商和模型、可见回复以及会话状态。共享相同模型但使用不同运行入口的路线分别验证。
2. 建立测试群，验证成员收到消息、按 @ 指定回复，以及回复能在群聊中读回。涉及多模型调度的更新，用不同供应商的已配置模型跑一次。
3. 在已授权的官方工具路线中，执行一个无副作用的任务，例如读取临时目录里的测试文件。核对实际工具返回和会话中的工具记录。涉及工具记录的修复，也检查重新打开会话能否读回记录。
4. 对本次改动涉及的其他功能，通过用户日常入口实测。记录候选版本、Harness 版本、模型和入口、观察到的结果以及阻塞原因。每条检查标记为通过、失败或未验证。遇到缺少登录、权限或额度时，注明具体原因。

自动化回归结果单独记录。使用模拟模型、只检查连通性或只查看模型列表，都不能计为真实使用通过。
