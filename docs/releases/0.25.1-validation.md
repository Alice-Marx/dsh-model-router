## Problem and resulting behavior

- Harness Desktop 0.2.1-rc.3 is outside 0.25.0's exact Host peer range. This update adds 0.2.1-rc.3 while retaining the existing 0.2.0-rc.1, 0.2.0-rc.2 and 0.2.1-rc.2 declarations.
- Source development pins the published 0.2.1-rc.3 SDK graph and regenerates the Desktop client against that SDK. SDK checks must inspect the Host/client interfaces actually imported by the plugin, including remotes, settings, tools, model execution and the client loader.
- Current bilingual installation examples and workbench documentation identify 0.25.1 and the declared Host versions. Historical release notes, tags and acceptance reports retain their original versions and evidence.
- API monetary accounting, the independent subscription quantity ledger, durable execution checkpoints, progress and cancellation retain their existing behavior. This compatibility update does not introduce a state schema beyond v3 from 0.25.0.

## Boundaries and upgrade

The [official rc.3 release](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3) adds sidebar/session menus and changes the official API-key route's model-list refresh. The router's existing `sidebar.panellist` registration remains visible by default and participates in the new menu; no forced pin preference is needed. Its existing asynchronous `session.modelCatalog` call continues to consume the Host-owned directory. No provider endpoint, key lookup or model identifier is reimplemented by this update.

The rc.3 SDK dependency graph and offline contracts provide source/build evidence. They do not establish that every declared older Host has been newly tested in an installed Desktop, or that a vendor login, model identity or account entitlement is available. Installed-DSH end-to-end acceptance and new paid-provider/vendor CLI inference are not claimed unless separately recorded with their actual date, environment and results. Earlier real execution evidence remains in the [0.20.0 report](0.20.0-validation.md); API/subscription separation and accounting limits remain in the [0.25.0 report](0.25.0-validation.md).

Fully quit Harness, including tray and all Host processes, before updating the plugin; restart after installation. Back up profile/state data before updating or downgrading. Existing v3 state is retained; plugin versions predating schema v3 cannot read it. Do not erase unresolved reservations or replay interrupted paid work to test compatibility.

Subscription quantities are observed usage, not remaining vendor quota. API estimates are not a hard provider billing cap. Mock execution, local preview and successful automated tests do not validate provider billing or deliverable correctness.
