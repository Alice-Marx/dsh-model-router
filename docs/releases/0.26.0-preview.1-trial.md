# 0.26.0-preview.1 — isolated trial / 隔离试用

## Install / 安装

This is an opt-in preview, not a stable release or an automatic migration tool. Use a separate DSH test home/profile; do not point it at production Bot, Session, workspace, funding or CLI data. Back up the original home and fully quit Desktop, including its tray process, before making your own installation changes.

这是手动选择的试用版，不是稳定版或自动迁移工具。使用独立 DSH 测试 home/profile，不要指向生产 Bot、Session、工作区、资金或 CLI 数据。先备份原 home；用户自行变更安装前应完全退出 Desktop（含托盘）。

- In the isolated Desktop profile, open **Plugins → Add plugin** and enter `@ljwei-stak/dsh-model-router@0.26.0-preview.1`, then restart that test instance.
- 在隔离 Desktop 配置中打开 **插件 → 添加插件**，输入 `@ljwei-stak/dsh-model-router@0.26.0-preview.1`，安装后重启测试实例。
- With DSH CLI already targeting your isolated test installation: `dsh plugin --profile desktop add @ljwei-stak/dsh-model-router@0.26.0-preview.1`.
- DSH CLI 已明确指向隔离测试安装时，可运行上述命令；不要对正常使用的 `desktop` 配置盲目执行。
- Exact npm package: `@ljwei-stak/dsh-model-router@0.26.0-preview.1`; npm channel: `preview`, never `latest`. `npm install -g` alone does not register a Desktop plugin.

## Try first / 建议先试

1. Check that the combined DS Bot + Model Router interface loads and that existing stable installations remain separate. Create only disposable test Bots and workspaces.
2. Inspect exact-model settings, route previews, dependency plans, funding/receipt displays and terminal lifecycle UI. Planning does not require a provider call.
3. If you choose to run a real model or CLI yourself, configure your own credentials and explicit permissions in the test instance. Execution can incur provider charges and access the selected workspace. This release's offline tests do not verify your account, login or model.
4. Record the exact package, DSH/Node/OS versions, test profile type, minimal reproduction and redacted error. Do not include tokens, credentials, private paths, Session contents or funding data in bug reports.

先检查合并界面、模型精确绑定、路由预览、依赖计划、资金/收据展示和终端生命周期。仅创建可丢弃的测试 Bot/工作区。用户自行执行真实模型或 CLI 时，需在测试实例配置自己的凭据并确认权限，可能产生费用；本版离线测试不证明用户的账号、登录或模型可用。反馈应包含具体版本、系统与最小复现，不要上传密钥、私人路径、会话或资金数据。

## Known limits / 已知限制

- Formal integration status remains 0/20 work packages, 44/63 scenarios, M0 11/12 and G1–G4 in progress; all 40 feature rows retain `behaviorVerified=false`. A preview is not full product acceptance.
- Complete C1–C10 migration, provider instance/path/ownership/generation authority, consistent cross-provider capture, production activation, all-domain stop-write and post-activation rollback remain unproven/closed. Several migration modules are source-only and absent from the npm runtime. Do not use repository migration scripts against real data.
- Real vendor/login/model, real cross-machine topology, full Windows/POSIX/DPI/UAC/RDP matrices, long-duration performance, deployment and final stable-release gates remain open. Platform skips and fixture checks do not verify these environments.
- The remote computer agent is a private source subproject, not a separately published npm product in this release. Loopback fixture results do not establish production deployment.
- The current full regression is not green: the first candidate stopped with14 failing upstream-inclusion fixture tests and never entered its native phase. A Git-isolation fix has four logged passing follow-ups but no final exit receipt; the new offline Host probe also has no final receipt. These remain failed/interrupted/not_run, not passes. Read the dated validation report before evaluating.
- The E164 strict frozen dependency installation failed when `better-sqlite3@13.0.3` implicitly ran `node-gyp rebuild`: the local node-gyp could not recognize Visual Studio 18. Loading the shipped Windows x64 prebuild succeeds, but this does not turn the failed install into a pass. Installation through your DSH/Node platform still needs testing. Do not disable TLS verification or change system compiler/credential settings to bypass a failure.

正式状态、完整迁移、真实跨机/平台/账号验收均未因试用版发布而提升。SQLite 原生依赖安装仍有本机编译器识别问题；已有 Windows x64 预编译模块可加载不等于干净安装通过。若安装失败，请保留日志并反馈，不要关闭 TLS 校验、篡改凭据或操作生产数据绕过。

本次完整回归并非全绿：首候选有14个上游纳入夹具失败，原生阶段未运行；Git隔离修复后的整组定向测试和新Host探针均无最终退出收据，不记通过。实际tarball在隔离固定rc.3 Host解析桥下可导入，SQLite可加载，但不代表全新Desktop安装通过。

## Recovery / 恢复

Stop using and remove only the disposable test installation/profile. Keep production data and original backups untouched. Installing stable 0.25.5 does not constitute a data-schema downgrade or migration rollback; never point an older version at data modified by a newer test version. The preview does not provide an accepted post-activation rollback procedure.

停止并移除可丢弃的测试实例即可；不要改动生产数据或原始备份。重装稳定版不等于数据格式降级或迁移回滚，不要让旧版读取被新版试用修改的数据。

See the [validation report](0.26.0-preview.1-validation.md) for actual dated results and skips. Publication outcome is established only by the actual npm registry entry and GitHub prerelease assets, not by this guide.
