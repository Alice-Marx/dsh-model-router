# 0.25.3 release acceptance

Date: 2026-10-26. Package: `@ljwei-stak/dsh-model-router@0.25.3`.

## Behavior

ZCode CLI now offers npm in addition to the existing default GitHub Release
method. npm installs the fixed `@ljwei-stak/zcode-cli@latest` package using the
common npm prefix and configured registry. The selected method controls
installation, update, repair, removal, version checks and terminal/task entry
selection. The two version channels retain separate caches and in-flight
requests; missing or invalid npm installations do not use an archive copy.

The npm package includes the complete runtime archive. The plugin verifies its
metadata, launcher, payload manifest and compressed runtime against the exact
npm registry release, then checks every expanded runtime file before direct
launch. It reuses a valid package runtime; when install scripts are disabled it
prepares a dedicated verified cache under the DSH state directory. It does not
run the npm bootstrap in the Host or fetch a separate GitHub runtime. npm
uninstall removes its selected package and may retain the verified runtime
cache, configuration and sessions.

Node 24.14.0 or a newer Node 24 remains required. The existing configured CLI
model, login commands and approved editable-workspace boundary are preserved.

## Validation

- Pinned frozen pnpm installation with strict peer dependencies passed.
- Complete local regression suite: 1,218 tests, 1,215 passed, 0 failed,
  3 environment skips on Windows / Node 24.20.0. Actual Desktop client rebuild
  (980,828 bytes), client check, bilingual README pairing and offline preview
  compilation passed. The new npm choice and its effective command/directory
  were visually inspected in the local workbench preview.
- Source-specific latest caches, captured health settings, npm prefix binding,
  method switching, runtime integrity, unsafe links, missing/changed resources,
  concurrency and decompression limits have targeted regressions.
- Actual Windows / Node 24.20.0 smoke used the published npm package 3.16.2.
  Both ordinary installation and explicit `ignore-scripts` installation passed
  through the real Host install job, npm registry attestation, version/help,
  terminal/login launch resolution and managed readiness. Each was uninstalled
  through the selected npm method; sibling files and session fixtures remained.
  Missing npm after uninstall could not become an archive or cached-runtime
  installation. No model request was made.
- Publication is gated on Windows/Linux CI and npm archive verification against
  the committed Git files and runtime import closure. Exact CI references,
  counts, package digests and anonymous post-publication download checks are
  retained in release notes and the dated export evidence.

This verifies installation and launch contracts, not new paid inference or an
installed-DSH UI end-to-end run. Native macOS operation is not newly tested here.
