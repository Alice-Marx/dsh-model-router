## 为什么先改搜索和评估

[RouteLLM（2024，更新 2025）](https://arxiv.org/abs/2406.18665) 使用查询与偏好数据学习路由。我们尚无本项目的多模型同题质量标注集，不能仅把加权分数改名为“学习概率”，也不能套用论文的节省数字。

[RouterBench（2024）](https://arxiv.org/abs/2403.12031) 将质量与实际推理费用放在同一评估框架中。[LLMRouterBench（2026-01）](https://arxiv.org/abs/2601.07206) 则指出正确专家召回不足，以及多种复杂方法与简单基线之间的差距有限。我们借鉴其评估原则，优先补足候选保留、明确基线和质量—成本核验；本实现不是这几篇论文的算法复现。

## 已实现的改变

1. **候选池无关的成本尺度。** 使用当前工作包的 token 估价（含输入、输出、缓存及推理开销），成本效用为 `1 / (1 + C / C_ref)`。参考价格固定为 input=1、output=5 USD/百万 token，缓存参考价为 1；它是偏好尺度，不是厂商价格或学术最优参数，未来须在验证集调参。加入无关极贵模型不再压平原有成本差。
2. **保住预算可行候选。** 在质量达标候选中，截断到 12 个候选前先保留已知价格的最便宜路线，以及最高分、最高质量路线；没有路线达标时，沿用质量前 3 名的放宽候选范围。这不是全模型池预算可行性的证明。未知价格不得证明有限预算可行。
3. **依赖安全的剪枝。** 存在工作包依赖时停用局部路线 Pareto 剪枝：某路线单步稍差，仍可能因避免后续交接而使整体更优。独立工作包的剪枝还必须保留实际效用优势。
4. **精确/近似分开报告。** 保留候选的笛卡尔空间不超过 4,096 时穷举精确求解；更大空间用宽度 256 的 beam，并在预算约束下保留低成本前缀。精确仅指“保留候选 + 当前代理目标”最优，候选截断和质量估计仍可能漏掉真实最佳模型。
5. **去掉无证据的加分。** 不再按模型名给整合阶段固定奖励；修复未知模型质量反馈重复加分，按每个工作包分别标记质量证据。派生类别平均分和无来源标记的旧类别缓存不充当未测任务的已知质量；显式 overall 仍是跨任务代理先验，不是逐题证据。费用基线同样过滤图像能力不匹配的路线。模型评分、复杂度、延迟先验、质量门槛和交接罚分仍是可审计启发式，**不是答对概率或质量保证**。

规划输出的 `optimization.search` 报告搜索方式、组合数、扩展状态和 beam 截断；`qualityFiltered`、`paretoPruned`、`candidateTruncated` 分别报告质量筛选、局部剪枝、数量截断；`localParetoDisabled` 与 `optimalityScope` 标明求解边界。

## 已验证与未验证

`tests/routing-optimizer.test.mjs` 包括真实复现的预算候选丢失、依赖交接、无关极贵路线、重复反馈反例；小规模随机 DAG 与独立完整枚举比较，并验证输入顺序不变性和未知价格隔离。

这些测试证明所覆盖输入下的求解行为，**不证明真实回答质量、费用节约或厂商实际模型能力**。仍缺本项目同题多模型质量矩阵、独立校准集、时间/域外测试和真实付费调用验证。本轮没有训练神经路由器、没有额外模型调用，也没有自动付费探索。

## 离线结果矩阵评估

从完整源码运行，不依赖账号，不发送网络请求：

```powershell
npm run eval:routing -- tests/fixtures/routing-evaluation.synthetic.json
node scripts/evaluate-routing.mjs --help
```

内置文件明确标为 **synthetic**，仅用于验证指标和工具，不能作为路由质量基准。真实数据文件可按如下结构准备：

```json
{
  "provenance": "recorded",
  "models": ["p/cheap", "p/strong"],
  "validation": [{"id":"v1","domain":"code","results":{"p/cheap":{"correct":true,"costUsd":0.001},"p/strong":{"correct":true,"costUsd":0.01}}}],
  "test": [{"id":"t1","domain":"code","selected":"p/cheap","routingCostUsd":0,"results":{"p/cheap":{"correct":false,"costUsd":0.001},"p/strong":{"correct":true,"costUsd":0.01}}}]
}
```

每道题需同一固定模型池的完整结果；正确性标签应来自客观测试或明确的独立评价标准，不能把“请求成功”当作“答案正确”。记录实际 input/output/reasoning/cache token、重试及账单成本；路由器费用另计 `routingCostUsd`，不要漏计已经发生的级联调用。遗漏该字段默认按 0 计算；其他基线的路由开销未测量，报告不是所有策略的完整账单核验。`selected` 必须是事先记录的选择，而非查看测试答案后补选。评估器不代你训练或选择 test 的路线，也不能验证采集数据是否真的无泄漏。

validation 只用于选择 best-single（宏领域正确率、费用、ID 稳定排序）与 cheapest-single（平均费用）；test 用于报告记录路由器、单模型、固定种子随机和事后 Oracle。不同 split 的 ID 禁止重叠，但重命名重复题等语义泄漏仍须采集者检查。

指标包含微/宏正确率、领域正确率、平均模型/路由/总费用、与 Oracle 的正确率差，以及“只有 1 个、2–3 个、4+ 个模型正确”的正确专家召回率。每桶召回为选中正确模型的题数除以该桶题数，空桶为 `null`，不是候选 `recall@k`。Oracle 使用 test 标签，是事后参照，**不可部署**；模型都错误时不算可召回专家。

本工具只评估已记录的单次选择与费用，不重放多工作包 DAG，不比较旧/新算法的真实输出，也不自动给出预算扫描、校准或置信区间。后续应先建立 train/calibration/validation/test 和时间外数据，再固定同一模型池与任务集比较 0.15.0、当前开发算法、单模型及 Oracle，绘制同预算质量/同质量成本曲线；没有这些数据时只报告工程正确性。

`scripts/routing-paired-statistics.mjs` 是另一个科研模块，可对已冻结选择并连接好的真实逐题结果计算整组、领域分层配对区间。它支持连续 `quality`，不改变上述二元工具的输入合同；近似 bootstrap 不是有限样本风险认证，更不能对最新任务均分冒充逐题使用。聚合审计从源码运行 `npm run audit:livebench -- --input-dir <原始文件目录> --output <独立输出文件>`，详见 LiveBench 文档。
